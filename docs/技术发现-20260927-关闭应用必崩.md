# 技术发现 — 20260927 — 关闭应用必崩（Microsoft.UI.Xaml.dll 访问冲突 c0000005）

> **级别：P0（应用每次关闭都产生崩溃转储与 WER 上报）**
> 状态：**已确证，未修复**（根因在 WinUI 原生卸载路径，修复需改动代码，待授权）
> 发现者：主代理本轮 WER 闭环复验时发现；**非本轮改动引入**（时间线见 §4）

---

## 一、结论摘要

**PCMig.WinUI 每一次正常关闭都会崩溃。100% 复现，与用户是否交互无关。**
崩溃发生在 WinUI **原生卸载路径**内，托管层**没有任何未处理异常**。

| 项 | 值 |
|---|---|
| 故障模块 | `Microsoft.UI.Xaml.dll` **3.2.3.0** |
| 异常码 | `c0000005`（**访问冲突 / Access Violation**） |
| 故障偏移 | `0x00000000007f9880` |
| 进程 | `PCMig.WinUI.exe` 1.0.0.0，映像基址 `6a870000` |
| 稳定标识 | 故障桶哈希 `0e67f1d8e74e25d1cc9211eba0f2f99a`（14 次全部相同） |
| 转储 | `%LOCALAPPDATA%\CrashDumps\PCMig.WinUI.exe.<pid>.dmp`，每个约 **8.5–8.8 MB** |

## 二、复现方法（任何人可复验）

```powershell
$exe = '<仓库根>\src\PCMig.WinUI\bin\Release\net8.0-windows10.0.19041.0\win-x64\PCMig.WinUI.exe'
$t0 = Get-Date
$p = Start-Process $exe -PassThru
Start-Sleep -Seconds 8                      # 等窗口出现，不做任何交互
$w = Get-Process -Id $p.Id
$w.CloseMainWindow() | Out-Null             # 等价于点窗口的 ✕
# 进程约 4 秒后自行退出（不是被强杀）
Start-Sleep -Seconds 8
Get-ChildItem "$env:LOCALAPPDATA\CrashDumps" -Filter 'PCMig*' |
  Where-Object { $_.LastWriteTime -gt $t0 }        # => 必然出现新 .dmp
```

**判据**：只关心"**新增转储 + 新增 WER 事件**"，不看进程退出码
（本项目环境里强杀也表现为 `exit code 1`，退出码不可用）。

- **不是强杀造成的**：`CloseMainWindow()` 后进程**在 4 秒内自行退出**，脚本未执行 `Stop-Process`。

⇒ **崩溃点在关闭/卸载序列，不在任何交互路径上。**

## 五、已排除的假设

| 假设 | 排除证据 |
|---|---|
| 由本轮 Panel Exit / Motion 改动引起 | 首崩 9/26 23:21 早于改动 9/27 18:48 |
| 由 `WindowMinimumSize` 窗口子类化引起 | 该文件 9/27 14:59 才存在；首崩早于它 |
| 由某次具体交互（切页/开面板）引起 | 无交互的纯启停同样崩 |
| 由强制终止（`Stop-Process -Force`）产生转储 | 进程自行退出，未强杀；对照 A/B 均崩 |
| 托管未处理异常 | `App.UnhandledException` 与 `FirstChanceException` 均**无记录**；`poc-startup.log` 只有 `OnLaunched start/activated`，**无异常行** |

### 诊断钩子为何没抓到
`App.xaml.cs:22` 的 first-chance 钩子仅在 `PCMIG_DIAG=1` 时挂。
本轮试过 `$env:PCMIG_DIAG='1'` 后 `Start-Process`，结果 **`FirstChance` 记录数 = 0**
⇒ **该环境变量未继承到 WinUI 原生宿主**，钩子实际未生效。
（`setx` 属持久化注册表改动，**未做**。）

## 六、建议的排查方向（**未执行**，需授权）

1. **用 `PCMIG_DIAG=1` 的持久化方式重跑**，抓关闭阶段的 first-chance 堆栈
   （`setx` 或从已设该变量的 shell 启动 —— 属系统改动，待授权）。
2. **读转储**：`%LOCALAPPDATA%\CrashDumps\PCMig.WinUI.exe.<pid>.dmp`（8.5 MB，minidump）
   用 WinDbg/cdb 载入，取 `Microsoft.UI.Xaml.dll+0x7f9880` 的**符号化调用栈**
   （需 Microsoft 公共符号服务器）。
3. **二分法定根因**：在 `App.xaml.cs` / `MainWindow.xaml.cs` 的关闭路径上
   逐个移除可疑接线（XAML 资源释放、`Window.SubclassProc`、事件订阅、
   `DeveloperVisualTuning` 的运行时资源改写），每次只撤一处，复跑本文 §2 的判据。
   **注意**：`DeveloperVisualTuning` 会在运行期改写主题资源，
   若它在关闭时未恢复/未释放，正是"原生 XAML 卸载时访问已释放资源"的典型形态 ——
   **这是与 `Microsoft.UI.Xaml.dll` 内访问冲突最吻合的候选**，但仍需实验证实。
4. **临时缓解（不修根因）**：若需要"关闭不产生转储"的干净闭环，
   可在关闭路径改用 `Environment.Exit(0)` 跳过 XAML 卸载；
   **这会掩盖问题，不建议作为交付方案**，仅可用于区分"卸载序列"与"更早阶段"。
