## 二 本版做了什么（v0.5.1 = v0.5.0 的可信度紧急修正版）

**不是新功能版；功能与界面与 v0.5.0 一致。**

   - `src\PCMig.Core\Transfer\TransferOrchestrator.cs`：修正 `OutputLine` 委托注册顺序，使**真值错误处理**（字节回冲 / 错误码 `112`·`39` 写满熔断 / 错误风暴熔断）**优先于**界面转发。此前 UI 订阅方一旦抛出异常，会经 `RobocopyRunner` stdout 泵里的空 `catch` 被吞掉，并**连带跳过**其后注册的真值错误处理器 ⇒ 回冲与熔断双失效。
   - `src\PCMig.WinUI\Presentation\MigrationSessionViewModel.cs`：`AddFail` 改为在界面线程更新失败列表（引擎线程直接改 `ObservableCollection` 的跨线程风险）。
   - `src\PCMig.Core\Transfer\RobocopyRunner.cs`：两处空 `catch` 改为可观测日志，异常不再静默消失。
2. **P3 收尾**：删除零引用 `src\PCMig.WinUI\Presentation\ProgressMotionDriver.cs`（−818 行）；修正 `src\PCMig.Core\Models\Models.cs:277` 的 `TargetBytes` 过时注释；`**/TestResults/` 纳入 `.gitignore`。

## 八 环境踩坑（能省几小时）

1. ★**PS 5.1 把没有 BOM 的 `.ps1` 按 GBK 解码**★：中文（尤其全角括号）会吞掉闭合引号，报 `Missing ')' in method call` / `Unexpected token`，中文路径被毁。规则：`.ps1` 必须前三字节 `EF BB BF`；**`edit` 工具每次都会剥掉 BOM**（本轮 `tools\release.ps1` 与 `installer\pcmig.iss` 各中招一次）⇒ **改完立刻复核前三字节**，必要时用字节级手段补 `0xEF,0xBB,0xBF`。`installer\pcmig.iss` 无 BOM 时 Inno Setup 会把中文按 ANSI 读 ⇒ 图标名变乱码。
2. **Inno Setup 6 路径**：`%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`。
3. `$Pid` / `$host` 是只读自动变量 ⇒ 参数名改用 `ProcessId`。
4. `[IO.File]::ReadAllText('相对路径')` 按进程 CWD 解析 ⇒ 一律绝对路径。
5. 单命中 `(…).Count` 返回 `$null` ⇒ 用 `@(…).Count`。
6. 断言不许命中自己的注释。
7. **Build 前必须先 `Get-Process PCMig.WinUI,PCMig.Cli,PCMig.Gui | Stop-Process -Force`**，否则文件锁定产生 `MSB3027/MSB3021` 假失败。
8. 本机窗口激活只认 `Shell.Application` 的 `MinimizeAll()` + `UndoMinimizeAll()`；`SetForegroundWindow` / `SetWindowPos(HWND_TOPMOST)` / `PrintWindow` 都拿到陈旧或错误窗口。
9. 切换目标卷（挂/卸 VHD）前必须先关应用，否则 WinUI 主进程 `Responding=False` 并空转烧 CPU。
10. 本机 `python.exe` / `python3.exe` 是 Microsoft Store 执行别名存根；`py -3` = Python 3.14.7 可用。
11. `docs\更新日志.txt` 由 `docs\更新日志.md` 经 `md2txt.py` 转换：`## ` 会变成 `■ ` ⇒ **不能用 `(?m)^## v0.5.1` 去匹配 txt**。
12. `git show <ref>:<path> | Out-File -Encoding utf8` 作比对会因 CRLF/BOM 变换误判 ⇒ **正确做法是 `git hash-object -- <文件>` 与 `git rev-parse <commit>:<path>` 比内容哈希**。
13. `git status` / `git add` 输出中文路径为八进制转义，属正常现象。
