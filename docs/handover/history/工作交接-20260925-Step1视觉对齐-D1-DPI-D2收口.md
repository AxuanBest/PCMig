## 二、D1：空状态被裁切（根因 + 修法 + 收口）

### 根因（探针实测，非推测）
共享卡片内层 Grid 原为 `Auto / Auto / *` 三行；空状态 `EmptySharesHint` 与 `ListView` **同处星号行**：

- 星号行实测只分到 **50 DIP**，扣 `Margin="0,14,0,0"` 后单元格仅 **36 DIP**；
- 而 `EmptySharesHint` 内容固有高 **93 DIP**（图标 38 + 主提示 22 + 次级说明 19 + Spacing 7×2），且 `VerticalAlignment="Center"`；
- 居中后顶部越出单元格（origin y=644 < 容器 y=672）→ 图标只剩残片、第三件文字完全出界。

**消耗量**：卡片内 InfoBar 占 64（50 + 14 margin）+ 头部 64 = 128，卡片可用高仅 212 → 星号行只剩 ~50。
已排除项：Visibility=Visible、Opacity=1、全链 Clip=none、ListView 覆盖（Background=null 且实际高同为 36）、CornerRadius 裁切（无 Clip）。

### 修法（已落地）
1. 共享卡片内层行定义 `Auto/Auto/*` → `Auto/*`；
2. **删除卡片内 InfoBar**（同时满足 A8「InfoBar 不占 Shares 主工作区」）；业务状态文本改绑底部状态栏中列 `{x:Bind ViewModel.Status, Mode=OneWay}`，业务语义零丢失；
3. 空状态容器改 `Grid.Row="1"`。
4. **主控收口**：子模型曾按主控指令加 `MinHeight="120"`，实测该值使容器（120）大于星号行实得（114），**反而把次级说明顶出卡片内容区被横切**。已移除，改由 Batch A 压缩连接卡片来创造真实余量。

### 验收证据（修后）
- `EmptySharesHint` desired = actual = **[252,93]**，origin y=622 完全落在容器（608–728）内；三件子元素 actual 全部非零。
- 卡片行分配：修前 `Auto/64 + Auto/64 + 1*/50` → 修后 **`Auto/64 + 1*/114`**；卡片 Border 高仍 212（未靠加高窗口作弊）。
- 主控视觉判读：蓝色文件夹图标**完整**、两行文字**字形完整无裁切**、第二行读作「连接旧电脑后，可用共享将在这里显示。」、文字下方留白正常。
- 截图：`archive\screenshots\winui-d1-emptyfix2-20260925.png`。

## 三、DPI：进程 DPI 不感知（根因 + 修法 + 视口守恒）

### 审计结论
`src\PCMig.WinUI\app.manifest` **完全没有 DPI 声明** → 进程 DPI 不感知，125% 缩放下由系统做 1.25× 位图拉伸（`RasterizationScale=1`），字体与边缘发虚。

### 修法（纯 Shell / Presentation Runtime 配置，业务代码零改动）
1. `app.manifest` 增加 `dpiAware=true/pm` + `dpiAwareness=PerMonitorV2, PerMonitor`；
2. `MainWindow.xaml.cs` 尺寸逻辑改为 DPI 感知（详见下）。

### 关键陷阱与视口守恒（本次最重要的技术结论）
- 声明 PMv2 后 `AppWindow` 尺寸单位变为**物理像素**：原 `Resize(1440,900)` 会把 XAML 空间压成 1139×713 DIP，**破坏 Canonical 布局** → 必须先按窗口 DPI 换算。
- 进一步实测：`AppWindow.ResizeClient(w,h)` 的"客户区"**不含** `ExtendsContentIntoTitleBar` 覆盖的那条标题栏带，系统**固定多给一段高度**（本机 125% 实测 **+38px / +29.8 DIP**）。所以"请求 1780×1114 → 实得视口 1780×1152"。
- 因此不能用"增量补偿"，必须**先量出这段常量偏移、再从请求值里扣掉**。实现为一次性自校正（`OnRootSizeChanged`，只跑一次防抖）：
  - 目标常量 `CanonicalClientWidthDip=1424 / CanonicalClientHeightDip=891`；
  - `offset = 实测视口 − 目标`；`ResizeClient((目标宽−offsetW)×scale, (目标高−offsetH)×scale)`；
  - **必须把 `SizeChanged` 订阅放在首次 `ResizeClient` 之前**，否则首次布局同步完成、事件永不触发（已踩到并修复）。

### 验证证据
- 进程级外部核对：`GetProcessDpiAwareness` → **2（per-monitor）**，`GetDpiForWindow=120`（scale 1.25）。
- 校正后实测：`newSize = xamlRoot =` **1424×891.2 DIP**，`client=1780×1115`。
- accent band 与旧的 Canonical 实测**逐条重合**：页标题 260-297、卡片 413/567/696、下一步按钮 **929-982**、底栏 **1056-1070**。
- 原生光栅化证据：空状态图标蓝色墨迹由「一整块 42px」（位图拉伸糊成一片）变为「772-783 + 809-813 两段细带」（锐利描边）。
- 窗口可见高 1116 = client 1115 + 2px 可见边框 → **不存在多余系统标题栏条**（曾怀疑，已排除）。

### ⚠️ 旧证据作废登记（重要）
**DPI 修复前的全部像素级测量（含 1800×1125 系列截图、`impl-canonical.png`、以及 compare 页 `index.html` 里按 x10/y0 原点算出的 CSS 裁切参数）自本文件起视为旧证据，不得再作为验收依据。**
新基准：**`archive\screenshots\winui-canonical-dpi-20260925.png`，1782×1116，裁剪原点 (8,0)**。
