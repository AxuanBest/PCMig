#### ★ A 项真因（前三轮都修错方向，务必记住）

**本项目 `Application.Resources` 合并字典里定义的隐式样式（无 `x:Key`）不会被应用到实际控件。**

用两个"不可误判"的探针证实：
1. 在隐式 `TextBox` 样式里把 `Background` 设为 `#FF00FFFF` → 输入框**没有**变青色；
2. 在模板里加 8 DIP 纯红 `Border` → 页面上**找不到**红条。

改成**显式 `x:Key` 并写到元素上**后，红条立刻出现、文字位置随之改变。

**因此正确答案**：所有输入框必须显式指定
`Style="{StaticResource PCMigTextBoxCentered}"` / `PCMigPasswordBoxCentered`
（当前 8 个输入框已全部指定，**新增输入框必须补上，否则退回框架默认模板**）。

光学补偿用 `Margin` 并**按实测标定**（框恒为 y=270..316、中心 293）：
`Margin.Top=30 → +9.5 DIP`；`=14 → +1.5`；斜率 0.5 → **`Margin.Top=11` → +0.5**。

<!-- 浮雕兼容层：上一版的大面积上下渐变在此被彻底抹平（保留 key 以免旧引用崩溃），

**★ 关键认知：旧版确认成功的浮雕 ≠ 渐变铺面**，而是三个**独立叠加层**：

```xml
<!-- ① 方向性边缘光：左上最亮 → 顶部次亮 → 右侧转暗 → 右下最暗 -->
<RadialGradientBrush x:Key="EdgeHighlight" GradientOrigin="0.06,0.08" Center="0.06,0.08" RadiusX="1.25" RadiusY="1.25">
  <GradientStop Color="#33FFFFFF" Offset="0.00"/>
  <GradientStop Color="#1AFFFFFF" Offset="0.26"/>
  <GradientStop Color="#0AFFFFFF" Offset="0.48"/>
  <GradientStop Color="#0D000000" Offset="0.68"/>
  <GradientStop Color="#26000000" Offset="1.00"/>
</RadialGradientBrush>
<!-- ② 内部边缘：距轮廓 1px 处的极弱明暗，暗示表面厚度，绝不是传统 Bevel -->
<RadialGradientBrush x:Key="InnerEdge" GradientOrigin="0.06,0.08" Center="0.06,0.08" RadiusX="1.25" RadiusY="1.25">
  <GradientStop Color="#14FFFFFF" Offset="0.00"/>
  <GradientStop Color="#00000000" Offset="0.42"/>
  <GradientStop Color="#0F000000" Offset="1.00"/>
</RadialGradientBrush>
<!-- ③ ContactShadow：BlurRadius 3 / ShadowDepth 1.2 / Direction 315 / Opacity 0.09 / Color #FF0B1220 -->
```

**WinUI 移植时的坐标换算（已查官方文档确认，务必遵守）**：
> `MappingMode=RelativeToBoundingBox` 时，`Center/RadiusX/RadiusY` 的 `(0,0)` = **左上**、`(1,1)` = 右下；
> 而 `GradientOrigin` 的 `(0,0)` = **中心**。
> 参考：https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.media.radialgradientbrush

故 WPF 的 `GradientOrigin="0.06,0.08"` 等价于 WinUI 的
`Center="0.06,0.08"` + `GradientOrigin="0,0"`（这是关键坑，直接照抄会得到反方向的光）。

**移植结果（已在 `Materials.xaml` 就位，但当前未被引用）**：
```xml
<RadialGradientBrush x:Key="PCMigEdgeHighlight" MappingMode="RelativeToBoundingBox"
                     Center="0.06,0.08" GradientOrigin="0,0" RadiusX="1.5" RadiusY="1.5"> ... </RadialGradientBrush>
<RadialGradientBrush x:Key="PCMigInnerEdge"      MappingMode="RelativeToBoundingBox"
                     Center="0.06,0.08" GradientOrigin="0,0" RadiusX="1.5" RadiusY="1.5"> ... </RadialGradientBrush>
```

## 5. 环境与工具的关键事实（下一任必读）

### 5.1 视觉通道（本会话排查出的真因，**不是项目问题**）

用户配置的 `%APPDATA%\dsh-desktop\harness\settings.yaml` → `vision-toolkit:`：

```yaml
provider:
  baseUrl: <百炼 token-plan 端点>     # 用户付费端点，正确
  credential: ANIONEX_FREE_VISION   # 名字叫 FREE，但存的是付费密钥（已确认）
  model: qwen3.8-flash              # 原为 qwen3.8-max
timeoutMs: 120000                   # 原 30000 → 必须提高
```

**真因**：`qwen3.8-max` 是**推理型**视觉模型，对 437KB 完整界面截图生成 5867 个 reasoning token，
实测单次 **133.5 秒**；换 `qwen3.8-flash` 后 **33.1 秒**；而插件默认 `timeoutMs=30000` →
**每次都被自己的超时砍掉**。插件日志 48 条记录**零成功**，全是 `category=timeout upstream≈29.6s`。

实测证据（直连端点、与插件同参数）：
```
纯文本请求       1,951 ms
450B 纯色小图   17,574 ms（reasoning 772 tokens）
15KB 裁剪截图   17,729 ms（reasoning 548 tokens）
437KB 完整截图 133,464 ms（reasoning 5867 tokens）
```

**结论**：端点、密钥、模型名全部正确；**唯一问题是 timeoutMs 太小**。

### 5.3 截图/测量方法的关键坑（AI 反复踩过）

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 窗口每次启动位置不同（本次观测到 26/52/78/130/156/164/190/208/216/242 等） | 写死坐标就采到空白 | 每次重新测量 `ClientToScreen` |
| 客户端截图坐标 = 窗口内坐标（**不是**屏幕坐标） | 混淆两者会全错 | 图片坐标直接用 |
| **DVT 面板打开时会遮挡侧栏** | 测到的"卡面"其实是面板的白色 | **改完值必须关面板再截图** |
| 近白区 0/50/100 只差 2 个亮度单位 | 会误判"DVT 无效" | 用 `Card` 滑块或极端值、并采卡面而非背景 |
| 视觉模型对同一张图会给出**自相矛盾**的判断 | 不能当唯一依据 | **以像素测量为准**，视觉仅作交叉验证 |
| `SomColorBrush`/`LinearGradientBrush` 边缘使亮度阈值判定不稳 | "找卡片段"经常失败 | 用 `vision_ground` 定锚 + 同框同参数比对 |

### 5.4 工程坑

- **`PCMig.sln` 不含 WinUI**（第 8–16 行只有 Core/Cli/Gui/Core.Tests）
  → 构建解决方案**不会**刷新运行产物；**必须单独** `dotnet build src\PCMig.WinUI\PCMig.WinUI.csproj`
- WinUI 构建前**必须先 `Stop-Process PCMig.WinUI`**，否则 `apphost.exe` 被锁（MSB3027/MSB3021）
- 编辑含中文注释的 XAML 时，用**行级精确替换**；整块替换极易造成
  重复特性 / 注释提前结束 / 标签配对错误（本会话因此失败 6 次以上）
- PowerShell 引号与尖括号混用会解析失败 → 改用 read/edit 工具
