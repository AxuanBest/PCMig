### 4.1 根本原因：**方案选择错误，且纠错太慢**

|---|---|---|
| **1** | **最初选择"从 ISO 引导安装"**。这必然出现 `Press any key to boot from CD`（Hyper-V Gen2 UEFI **无法绕过**），把自动化推回给人 | 让用户反复点 UAC、开 Hyper-V 窗口按空格 —— **用户的核心不满** |
| 2 | 纠错太晚：直到用户明确抱怨"每一步都要我手动确认"才改用离线部署 | 浪费大量往返 |

### 4.2 L3 的技术根因链（**接手者务必避免**）

```
① 离线部署（DISM /Apply-Image + bcdboot）成功
      ↓
② unattend.xml 只放了 specialize + oobeSystem，未让 OOBE 真正跑完
      ↓
③ 系统停在 IMAGE_STATE_UNDEPLOYABLE
      ↓
④ Install-WindowsFeature 间歇性失败 / Install-ADDSForest 报
   "服务器名或凭据验证失败。无法创建或打开文件。"
   DNS 角色报 "试图在标记为删除的注册表项上进行不合法的操作"（ERROR_KEY_DELETED）
      ↓
⑤ 绕过尝试：手工把 ImageState 改成 IMAGE_STATE_COMPLETE + 重启
   → 重启后系统又改回 UNDEPLOYABLE（**每次启动都回退**）
      ↓
⑥ 但这次 Install-ADDSForest **成功**了（关键：先改状态 + 重启 + 角色已装齐）
      ↓
⑦ DC01 成为域控（DomainRole=5）、OU/组/用户建好、FS01 加域成功
      ↓
⑧ CLIENT01 的 PowerShell Direct 始终不可达 → 未能完成
```

### 4.3 我反复踩的技术坑（**请接手者直接抄这份清单**）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | **`.ps1` 必须 UTF-8 带 BOM**。我用 write 工具建的脚本是**无 BOM**，里面含中文 → PS 5.1 按 GBK 读 → 中文乱码 → **语法错误**（"缺少 }"） | 建立脚本后**必须**补 BOM：`[IO.File]::WriteAllText($p,$text,(New-Object Text.UTF8Encoding($true)))`；**跨机传输的脚本最好用纯英文** |
| 2 | **用字符串拼接生成 PowerShell 代码 = 转义地狱**。我在 `-Inline` 里嵌 here-string、嵌引号，反复生成出语法错误的脚本 | **绝不**用字符串生成代码。用 write 工具建文件，再用 `-ScriptFile` 或 **base64** 传输 |
| 3 | **PS 5.1 不支持在哈希表字面量里用 `try/catch` 表达式**：`@{x = try{...}catch{...}}` 直接语法错 | 先算到变量，再放进哈希表 |
| 4 | **`param()` 必须是最前面语句**（注释之后）；我写成 `$ErrorActionPreference='Continue'` 在前 → 语法错 | 严格遵守 |
| 5 | **`-File` 模式不能绑定数组参数** | 用 CSV 单 token 传，脚本内 `-split ','` |
| 6 | **`Set-Location` 不改变 .NET 当前目录** → `[IO.File]::ReadAllLines('相对路径')` 会失败 | 一律用绝对路径 |
| 7 | **脚本末尾的 `ReadKey` 在无人值守下不抛异常而是永久阻塞** → 把我的"管理员执行器"的 `Start-Process -Wait` 一起挂死（**这是最贵的坑**） | 所有脚本末尾改为 `if (-not $env:PCMIGLAB_HEADLESS) { … ReadKey … }`，执行器侧注入该环境变量 + 加作业超时 |
| 8 | **PowerShell Direct 会话结束时，`Start-Process` 启动的子进程会被清理**（无重定向时） | 必须带 `-RedirectStandardOutput / -RedirectStandardError`，子进程才能存活 |
| 9 | **在域控上不能用裸 `Administrator` 连接**（报"凭据无效"） | 用 `.\Administrator` 或 `DOMAIN\Administrator` |
| 10 | **`cmd.exe /c "... > log"` 在 UNDEPLOYABLE 状态下重定向会失败**（日志被占用/为空） | 用 `Start-Process -RedirectStandardOutput`（.NET API 更可靠） |
| 11 | **执行器串行**，长作业会阻塞后续所有提交 | 要么并行化，要么把长作业拆短 |
| 12 | `Dismount-VHD` 在 VM 运行时会失败（VHDX 被占用） | **灌盘前必须先 `Stop-VM` 并等待真正停止**；"已灌过的盘按大小跳过"是个好用的优化 |

### 4.4 关于"管理员执行器"（我搭的那套东西）

**设计意图**：因为 DSH 的 shell 是 **Medium 完整性级别、无法提权**，每步都要用户点 UAC → 我建了一个 SYSTEM 级计划任务做"命令队列执行器"，让用户**只授权一次**。

**它一度可用**（探针 `IsAdmin=True`、`Get-VM` 正常）。但：
- v1 因坑 #7 被挂死
- v2（加了超时 + HEADLESS 标记）可用
- **它本质上是我为了绕开权限限制而引入的间接层，增加了复杂度和故障面**

**接手者建议**：如果 DSH 能以管理员身份跑（或直接用管理员的 PowerShell 会话），**不要**再引入这种间接层。

## 五、给接手者的具体建议（**最重要的一节**）

### 5.1 【强烈建议】改用微软官方的 **VHD**，不要用 ISO 装

我在搜索时看到过 Evaluation Center 提供 **VHD 下载**（不只是 ISO），但**当时忽略了**。这是本末倒置：

```
Microsoft Evaluation Center → Windows Server 2025
  ├─ Windows Server 2025 | 64-bit ISO download
  └─ Windows Server 2025 | 64-bit VHD download   ← ★ 用这个！
```

**用 VHD 的收益**：
- **不需要安装程序、不需要 unattend.xml、不需要 OOBE** → 直接挂到 Hyper-V 就能启动
- 绕开本次失败链的 **②③④** 全部环节
- 首次启动会走一次少量 OOBE（可手工点一次，或用简单 unattend 补齐）
- **风险极低**

### 5.2 备选方案：手工装一台 → `sysprep /generalize` → 作为模板克隆

- 手工装**一次**（允许人工，因为只做一次）
- `sysprep /generalize /oobe /shutdown`
- 复制 VHDX 三次 → 三台 VM
- 缺点：sysprep 后仍需 unattend 应答（但比从零装简单得多）

### 5.3 【不要做】从 ISO 引导安装 + 期望全自动

- `Press any key to boot from CD` 在 Hyper-V Gen2 上**无法绕过**（网上说"把应答 ISO 设第一启动项就行"是**错的**）
- 唯一真正零按键的路径是 MDT/ConfigMgr 或 **离线 apply-wim**

### 5.4 如果坚持离线 apply-wim：unattend.xml 必须完整

- 必须有正确的 `specialize` + `oobeSystem`
- **`RunSynchronous` 里的命令必须保证返回 0**（我放了一条 `netsh advfirewall ... "文件和打印机共享"`，中文组名可能导致非零 → **中止 specialize**）
- 验证方法：装完立刻查 `ImageState` 是否 `IMAGE_STATE_COMPLETE`、`C:\Windows\Panther\setuperr.log`
- **兜底**：若仍 `UNDEPLOYABLE`，可"改 ImageState=COMPLETE + 重启"，实测**建域能成功**（但系统会在下次启动改回，属于 hack）
