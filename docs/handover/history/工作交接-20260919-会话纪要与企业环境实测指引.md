### 2.1 两类日志，两个位置（**记住这个**）

| 类型 | 根目录 | 说明 |
|---|---|---|
| **应用级日志** | **`<本机程序数据目录>\Logs\`** | 程序自身运行日志（启动、UI、异常、崩溃兜底） |
| **任务级日志** | **`<本机程序数据目录>\Jobs\JOB-<日期>-<时间>-<4位ID>\`** | **每个迁移任务一个目录**，含 Robocopy 原始日志 + 全部状态文件 |

`%ProgramData%` 在标准 Windows 上就是 `C:\ProgramData`。

> ⚠ **可被环境变量覆盖**：`PCMIG_JOBS` 若被设置，会改变 **Jobs 根目录**（便携场景用）。
> `Logs` 目录**不受**该变量影响，始终在 `%ProgramData%\PCMig\Logs`。
> 本机实测：`PCMIG_JOBS` **未设置** → 用默认路径。

### 2.2 应用级日志目录（`<本机程序数据目录>\Logs\`）

| 文件 | 内容 | 保留 |
|---|---|---|
| `app-YYYYMMDD.log` | **人可读文本**，格式：`{时间} [{级别}] [{机器名}/{PID}] {消息}` + 异常堆栈 | 31 份（按天滚动） |
| `app-YYYYMMDD.jsonl` | **结构化 JSON**（CompactJsonFormatter），便于程序/AI 解析 | 31 份 |
| `crash-YYYYMMDD-HHMMSS.log` | **崩溃记录**（GUI 未处理异常时写，含异常详情） | 不滚动，累积 |

- 编码：**UTF-8 带 BOM**（记事本/PowerShell 5.1 读中文不乱码）
- 默认级别：**Debug**（最详细）
- 本机实测存在：`app-20260919.log`(31.6 KB)、`app-20260919.jsonl`(63.3 KB)、`crash-20260918-*.log` 等

### 2.4 在公司电脑上，怎么快速拿到日志给 AI 分析

**方法 A：让程序自己告诉你路径（最省事）**

```powershell
# CLI 帮助里会打印详细日志目录
pcmig --help
#   → 详细日志：<本机程序数据目录>\Logs

# 任务跑完后，CLI 会打印 Job 目录
pcmig run ...
#   →  Job 目录: <本机程序数据目录>\Jobs\JOB-20260919-135946-e813
```

**方法 B：GUI 崩溃时会弹窗**，弹窗里直接写明"应用日志目录：…"

**方法 C：直接去目录（推荐给 AI 分析用）**

```powershell
# 打开应用日志目录
explorer "<本机程序数据目录>\Logs"

# 列出最近 5 个任务
Get-ChildItem "<本机程序数据目录>\Jobs" -Directory |
  Sort-Object LastWriteTime -Descending | Select-Object -First 5 Name,LastWriteTime

# 看某任务的最终状态（★ 判定成败）
Get-Content "<本机程序数据目录>\Jobs\<JOB目录名>\job-state.json" -Encoding UTF8

# 看某任务的 Robocopy 原始错误（★ 最有诊断价值）
Get-ChildItem "<本机程序数据目录>\Jobs\<JOB目录名>\logs\robocopy" |
  ForEach-Object { Write-Host "=== $($_.Name) ==="; Get-Content $_.FullName -Encoding Default }
  # 注意：Robocopy 日志是系统 ANSI/GBK 编码，用 -Encoding Default 才不乱码

# 看应用级最近日志
Get-Content "<本机程序数据目录>\Logs\app-$(Get-Date -Format 'yyyyMMdd').log" -Tail 100 -Encoding UTF8
```

**方法 D：一次性打包给 AI（推荐）**

```powershell
$job = Get-ChildItem "<本机程序数据目录>\Jobs" -Directory |
       Sort-Object LastWriteTime -Descending | Select-Object -First 1
$dest = "$env:USERPROFILE\Desktop\PCMig-日志包"
New-Item -ItemType Directory -Force -Path $dest | Out-Null
Copy-Item $job.FullName -Destination $dest -Recurse -Force
Copy-Item "<本机程序数据目录>\Logs" -Destination $dest -Recurse -Force
Compress-Archive -Path "$dest\*" -DestinationPath "$env:USERPROFILE\Desktop\PCMig-日志包.zip" -Force
# 把 zip 交给 AI 分析
```

### 2.5 给做日志分析的 AI 的提示（**重要**）

| # | 提示 |
|---|---|
| 1 | **判定任务成败看 `job-state.json` 的 `phase`，不要看 CLI 退出码** —— 产品在 `CompletedWithErrors`（含磁盘满、部分文件失败）时**也返回 0**（`Program.cs:570`）。这是本项目最容易搞错的一点 |
| 2 | **`logs\robocopy\object-*.log` 是原始证据**，含 Win32 错误码与中文描述。分析失败原因优先看这里 |
| 3 | Robocopy 日志编码是**系统 ANSI（中文=GBK）**，不是 UTF-8。用 `-Encoding Default` 读 |
| 4 | `app-*.log` 与 `job-*.log` 是 **UTF-8 带 BOM**；`.jsonl` 是结构化 JSON，适合程序解析 |
| 5 | `preflight.json` 里 `OverallPass` 为 false 且存在 `Severity="Error"` 的项 → **预检阻断**，此时根本不会开始传输 |
| 6 | 已知的预检阻断码：FAT32 单文件 >4GB、单目录 >65534 目录项（约 21844 个文件即触顶）、空间不足；`--yes` **不会**绕过这些 Error 级阻断 |
| 7 | 已知错误码对照（Private Test Lab 实测）：**112**=磁盘空间不足、**82**=无法创建目录或文件（FAT32 目录项上限）、**5**=拒绝访问、**2**=找不到文件、**59**=意外的网络错误、**67**=找不到网络名、**1219**=凭据冲突、**1326**=用户名或密码错误 |
