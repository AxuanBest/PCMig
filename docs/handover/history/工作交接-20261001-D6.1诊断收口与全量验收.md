## 六、本会话我犯过的真实错误（接手者请务必读，避免重犯）

这些都是**我自己**在实现/测试中犯的错，已修正并登记在 `docs\诊断系统实施-D6.1-进度.md` 的 R8–R15：

1. **规则在等没人发布的事件**：`DIAGNOSTICS_DEGRADED` 等 `DIA.CriticalLost/EventsDropped/Backpressure`，而运行时**从不发布** ⇒ 触发路径**永远是死的**。矩阵一生成就暴露了它。
2. **我自己的"假接线"**：把 `WriterBatchMaxBytes` 接到"带时间闸门的 flush"上 ⇒ 把 `WriterFlushIntervalMs` 调大后它**永不生效**。行为测试当场抓出，改为走无条件 flush 路径。
3. **静默失败的脚本**：用 PowerShell 替换 codec 注册表时**没匹配上却打印了"已注册"** ⇒ 9 个 VRF 载荷在离线端会被读成未知载荷。教训：替换后必须**计数核对**，不能只信脚本的输出。
4. **字典重复键是"能编译的定时炸弹"**：codec 里重复注册同一载荷名，**编译通过、运行时抛异常**。靠 grep 计数才发现（71/72 与 113/114 各一份）。
5. **重复定义了已存在的载荷类型**（`NetSmbSession`/`NetShareDiscovery`）⇒ 正确做法是给既有类型**加可选字段**，不是另造类型。
6. **切文件切多了**：按注释文本切 `PlanNetPayloads.cs` 时连带删掉一个类、留下孤立块 ⇒ 改为**整体重写**该文件，而不是继续打补丁。
7. **测试自身的错误**：用了错误 eventId（解析成别的载荷类型）；"逐字节一致"比较忘了 `PlannedUtc` 每次不同；假设"净化阈值 0 ⇒ 所有文件都算大文件"（实现把阈值下限钳到 1 MiB 且**矩阵值优先于 options**）。
8. **凭空发明 API**（`_ctx.Diagnostics.PublishCore(...)` 带命名参数）⇒ 编译立刻拦下。**先读源码再写调用**。
9. **链入式测试的编译上下文**：`MigrationSessionViewModel.cs` 被 `PCMig.Core.Tests` 按源码链入 ⇒ 新增的事件类型在两个项目都必须可见，漏 3 个 using 直接让 Core.Tests 报 16 个错。
10. **分配测量的污染**：`OffModePublishAllocatesNothing`（OFF 路径必须 0 字节）偶发失败，根因是 xUnit 测试线程本身是线程池线程、后台管线续体落到同一线程产生分配 ⇒ 改用**专用线程**测量（要求仍是 0 字节）。
11. **引入了新警告**：第一版配置项行为测试用了阻塞式等待 ⇒ 触发 xUnit1031×2。门禁明确"不得新增 warning"，已改为 `async/await`。
12. **不该用 PowerShell 做 UTF-8 中文文件的读写往返**：`.ps1` 的 `Get-Content`/`Set-Content` 往返曾两次损坏文件；`.NET` 静态调用按**进程 CWD** 解析路径，`cd` 无效 ⇒ 一律用**绝对路径** + `read`/`edit`/`write` 工具。

**留给大家的工作习惯（本会话证明有效）**：机器生成矩阵（会随源码重算）、must-have 清单卡门（缺关键观察点即测试失败）、行为测试优先于源码字符串断言（旧断言 `DoesNotContain("e.Key.ToString")` 恒真、抓不到 `"key:" + e.Key`）、失败信息**自证**（断言里带台账/cutoff/分支统计）。
