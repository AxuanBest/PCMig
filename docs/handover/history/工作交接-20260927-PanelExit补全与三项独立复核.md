## 二、Panel Exit 的运行时证据（可判读，非"编译通过"）

脚本：`archive\scripts\winui-panel-exit-verify.ps1`
方法：连拍 N 帧 → 量**面板区域平均亮度** → 看逐帧差是"单帧跳变"还是"多帧渐变"。

### 关闭按钮实测（修复后）

| 帧 | 0 | 1 | 2 | 3 | 4 | 5…13 |
|---|---|---|---|---|---|---|
| 面板区亮度 | 243.28 | 243.28 | **243.66** | **245.01** | **247.39** | 247.39（静止） |
| 逐帧差 | 0 | **+0.38** | **+1.35** | **+2.38** | 0 | 0 |

**判读：3 帧连续渐变（≈150ms）后到达背景基线 247.39 ⇒ 有出场动画。**
硬切只可能产生 **1 次**跳变并立即静止；修复前该路径是 `Visibility = Collapsed` 立即折叠，
**物理上不可能出现中间态**。故这组中间态本身就是"动画存在"的证据。

### 对照实验（很重要，用来验证测量方法本身）

同一脚本先测"**打开**"动作：面板区亮度 `246.36 → 246.45 → 246.55 → 246.63` 后长期静止，
最大逐帧差仅 **0.09–0.10**，即**测不到打开动画**。

**这说明**：本 harness 的时间分辨率（约 45ms/帧，且首次抓取有延迟）
**只够抓到一部分动画**。所以：
- 它给出的"**看得到渐变**"结论可信（关闭路径），
- 它给出的"**看不到动画**"结论**不可信**（打开路径就是假阴性）。

⇒ **不得用本 harness 判定"某处是硬切"**，只能用它确认"某处确有动画"。

### 两个踩过的坑（避免重犯）
1. **截图坐标系**：`uishot-winui.ps1` 产出的是**窗口裁剪图**，
   当窗口位于 screen (104,104) 时，**屏幕坐标 = 截图坐标 + 104**。
   我因此第一次把关闭按钮点到了 (1366,196)（落在内容区，什么都没发生），
   正确值是 **(1470,196)**。误判为"点击无效"一次。
2. **坐标偏移不能硬编码**：脚本里已改为实测 `GetWindowRect` 得到 `$ox/$oy`，
   但**截图 x 仍要额外 +104**（窗口裁剪图与屏幕原点不同）—— 这是两套不同的偏移，别混。

### 子代理推翻了我的错误诊断（记录，我认）
我此前判定"**PowerShell 5.1 的 COM 互操作在这个环境下不可靠，应改用编译型 .NET 8 程序**"，
并把这条判断推给了子代理。**这条是错的。**
真因：**CLR 对"派生 `[ComImport]` 接口 + 33 方法基类"的偏移计算错误** ——
`IMFSample : IMFAttributes` 即便 14 个自有方法全写对，`SetSampleTime` 仍 AV。
**修法：每个 MF 接口都平铺声明（不用 C# 继承）**；正确的 `[ComImport]` 在 PS 5.1 下完全可用。

### 一条我复现不出、故列为未定的争议
子代理称 `MF_MT_INTERLACE_MODE` 的 GUID 末段应为 `...b44ccd`，
证据是字节扫描 `mfplat.dll`：`ccd` 命中 1 次、`cc0` 命中 0 次（对照 `MF_MT_MAJOR_TYPE` 1 次）。
**我复现：`ccd` 0 次、`cc0` 0 次、对照 1 次。**
⇒ 我的扫描方法对这个 GUID **无效**（该 GUID 可能不以连续字节常量存储）。
**如实记录为"未定"，不采信任何一方，也不据此改代码。**
`winui-png-to-mp4.ps1` 里目前用的是 `...b44ccd`（与我原始备忘录一致）。

### MP4 作为"动效证据"的力度弱（如实说）
子代理自己指出：SHA-256 显示 B-sel 15/17 帧唯一、A-page 与 C-dialog 17/17 帧唯一，
但**相邻帧只差约 5/765** —— 即**近乎静止的静帧**。
MP4 技术有效，但**作为"看得见动效"的证据力度弱**，这是**素材问题不是编码问题**。

## 六、一个方法论教训：裁剪取证不能把图片边界当界面边界

我用裁剪图让视觉模型看细节，它把**我的裁剪框**当成了**界面边界**，
于是报出 **7 处"左边缘文字被切半"**（"验证完整性"→"佥证完整性"等）——**全是假象**。
**规则：用裁剪图取证时，必须只描述"元素自身容器的边缘"，
并明确告诉模型左右边界是裁剪造成的。**
