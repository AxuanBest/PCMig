## 二、ⓐ「已有任务」下拉为空（P1）— 根因与修法

**症状**：Step 2「已有任务」下拉只有「新建任务」，看不到磁盘上已有的任务（实测磁盘 8 个）。

**根因（两层，都在 UI 投影层 —— 与 P0 目录树同一类病）**：

1. **没有"打开界面即刷新"的时机。** 旧 WPF 壳构造时就调 `RefreshExistingJobs()`；WinUI 壳没有这一处。全仓 `RefreshExistingJobsAsync` 只有 4 个调用点，**全部在某个动作之后**（`PrepareAsync` 后 / 运行结束后 / 验证后 / 载入任务后）⇒ 首次进入 Step 2 时 `session.ExistingJobs` 恒为空。
2. **投影不跟随状态源。** 下拉不是绑定而是代码投影（`PushState()` → `SyncExistingJobsCombo()` 重建 `ComboBoxItem`）；而刷新是**异步**的（`Task.Run` + `Post`）⇒ 集合被填满发生在 PushState **之后**，此后再无 PushState ⇒ 下拉长期停在 `Step2SelectDataPage.xaml` 里硬编码的第 0 项「新建任务」。

**修法**（沿用用户在 P0 定下的"一个状态源 + 一个写入路径 + 一个投影机制"）：状态源与写入路径**不变**（`ExistingJobs` / `RefreshExistingJobsAsync` 仍是唯一写入者）；补两处**只读刷新时机**（`AttachSession` + `OnNavigated(SelectData)`）；订阅 `ExistingJobs.CollectionChanged` **变更即重推**；并按 P1-5 的合批纪律（一个待处理标志 + 一次 `DispatcherQueue` 回调）把"一轮刷新重建 N 次下拉"收敛为一次。

**证据**（环境变量门控探针 `PCMIG_STEP2_JOBS_QA=1` → `a6-jobs-qa.log`）：

```

修后  09:50:17.290  session.ExistingJobs=0  combo.Items=1  first=[新建任务]  jobs=[]
```

## 四、⑤ Step3 Pause/Resume 运行时验收 — 四项全部通过

| 验收项 | 结果 | 证据 |
|---|---|---|
| 对象初态「**待传输**」 | ✅ | `10-A6修复-证据截图\11`、`\12` |
| 进行中「**传输中**」 | ✅ | `\12` **单帧三态**：`object-000001` ✓已传输(707 MB)、`object-000002` **传输中 (0 B/505 MB)**、`000003/000004` **待传输** |
| **Pause 是否真停** | ✅ **真的停住** | 作业日志 `12:21:18.186 任务已暂停（Cooperative），等待 resume 或取消`；停在 **paused / 2/3 对象**；`\11` 显示状态句 + 2 个 ✓已传输 + 1 个 待传输 |
| **Resume 是否继续** | ✅ **且不重传** | `12:22:58.829 传输开始: 共 3 对象, 已完成 2, 待传 127.83 KB` → `12:23:00.579 阶段结束: "Completed"（3/3，失败 0）`；目标落盘 3008 文件 / 1,271,005,043 B；`pause.request` 已清除 |

**关键机制（实测）**：`TransferOrchestrator` 是**协作式**暂停（`Cooperative = 跑完当前对象停`）。505 MB 的任务只用 **2.7 秒**（≈500 MB/s）就跑完，暂停请求赶不上任何对象边界 ⇒ 任务照常完成（`pause.request` 残留）。把暂停点击提前到开跑后约 0.9 秒、任务加大到 **1.18 GB / 3 对象**后，暂停在**第 2 个对象结束后**精确生效。
