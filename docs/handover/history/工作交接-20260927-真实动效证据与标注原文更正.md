## 二、本轮产出的真实动效证据

### 抓帧方法（关键：先拍再点，不能先按再拍）

**踩过的坑**：第一版脚本用"先 `MouseDown` → 再连拍 → 再 `MouseUp`"，
结果 **18 帧逐帧变化全为 0** —— 因为**导航在连拍开始前就已经完成**，整段拍的是静止末态。
**改为**：先 `MouseMove` → **开始连拍** → 中途触发点击 → 拍完 → 再补一帧末态。

### 帧序列（`motion-real\v00..v17.png`）

| 帧 | 含义 | 字节 |
|---|---|---|
| `v00` | 点击前（step1 静止） | 325,143 |
| `v01`–`v04` | 过渡早期 | 325,010 / 325,028 / 325,017 / 325,059 |
| `v05`–`v13` | **单调递减的过渡中段** | 324,811 → … → 324,393 |
| `v14`–`v16` | 过渡末段 | 324,329 / 324,327 / 324,400 |
| `v17` | 点击后（step3 静止） | **310,714** |

**判读**：`325143 → 渐进序列 → 310714`。
**单调渐进**是动画的特征；**硬切**只会在一次帧间隔内从 325143 直接跳到 310714。
⇒ **这组帧真的记录了页面切换过程**，不是静帧。

## 六、确认为真缺陷的两项（XAML 层已定位）

### 1. `PCMigPrimaryButton` 的 `TopSheen` 在 `Padding` 之内（对应用户"按钮高光混乱"）

`Themes\Controls.xaml:49`：

```
<Border x:Name="Root" ... Padding="{TemplateBinding Padding}" ...>   <!-- Padding = 20,12 -->
  <Grid>
    <Border x:Name="TopSheen" Height="16" VerticalAlignment="Top" CornerRadius="12,12,0,0">
```

`TopSheen` 是 **`Root` 的 `Padding` 之内**的一层 16px 白色渐变，
`Root` 自己又有 `BorderBrush="#86FFFFFF" BorderThickness="1"`。
⇒ 用户原话「**外面一个框，里面好像还有一个高光就是已经混乱了**」**根因就在模板层级**。
**只改颜色或高度无效**。**未修（属模板层改动，需授权）。**

### 2. Dev 面板第 4 个按钮被裁（已在上一份交接确证）

内容宽 316 DIP，四按钮需 ≈374 DIP，溢出 58 DIP；面板内缘右缘 x=1390 处**竖直硬切**。

### 3. 徽章"无阴影无高光无立体感"（对应用户原话）
`PageBadge`（`Step1ConnectPage.xaml:21`）= `AccentGradientBrush` + `CornerRadius=17`，
**无 `Shadow`、无 sheen 元素** ⇒ 平涂。用户说"每一个功能模块页面都是这个问题"。
**未修（视觉层改动，需授权）。**

### 4. `PCMigTextBox` 的 Padding 不对称（"文字未上下居中"的可疑根因）—— **实测不支持该判断**

`Themes\Controls.xaml:90` 基准样式是 `Padding="14,8"` + `VerticalContentAlignment="Center"`（对称、居中）；
`Step1ConnectPage.xaml:22` 的 IP/用户名框覆盖成 `Padding="42,8,14,8"`，
`:23` 的搜索框覆盖成 `Padding="40,8,12,8"`（左侧留给图标），
且搜索框容器里另有 `<FontIcon ... Translation="0,-0.5,0" />`（**仅 −0.5 DIP**）。

**实测（用户名输入框，判据可信：墨迹 13px / 59 像素 / 阈值 62）**：

| 项 | 当前构建 `final3` | 用户标注图 |
|---|---|---|
| 框（截图坐标） | y 325..371（高 47） | y 324..370（高 47） |
| 文字墨迹 | y 343..355（高 13） | y 342..354（高 13） |
| **墨迹盒中心 − 框几何中心** | **+1 px** | **+1 px** |
| 上留白 − 下留白 | −3.19 px | −3.19 px |

**⇒ 逐项完全相同：从标注时到现在该处没有任何变化；文字相对框只有 1px 偏移**
（低于 13px 墨迹高度的 8%，属亚像素/抗锯齿量级）。

**⚠️ 作废的测量**：IP 输入框那次判据失效——把整框渐变都当成了"文字"
（测得墨迹 y 257..316 覆盖整框 60px），**该次数据不可用，已丢弃**。

**结论（诚实版）**：与徽章居中一样，**我测不出用户看到的问题**（≤1px），
也**不声称"已修复"**——我从未改过任何居中相关代码。
用户原话是「按照我的画线方法来进行标记，观察的话，完全就是没有居中」，
若这是**视觉重心（optical centering）**层面的判断（字体 ascent/descent 导致
数字与文字的行框虽居中、但视觉重心略偏），那么 1px 级的像素测量**不足以反驳**，
需要按"视觉重心"重新定义验收口径。**需用户指认具体元素与判定标准。**
