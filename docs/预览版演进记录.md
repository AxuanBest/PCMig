# v0.5.4 预览版演进记录（Public 审核摘要）

本文是 v0.5.4 全部本地预览版的**公开发布摘要**，用于说明各轮预览版修了什么、验证到什么程度、还剩什么问题。

- 七轮预览版均为**本地实验版本**，不属正式发布链：未 push、未打 tag、未发 GitHub Release、未运行 `tools/release.ps1`。
- 当前正式稳定版仍为 **v0.5.3**。
- 原始 QA 报告、逐趟账本、回归日志与 UIA 证据保留在内部研发工作区（含企业真实业务数据与内网地址），不随公开仓库分发。

### 演进主线

```
阶段一 可信度（P1 → P2）      进度不虚报、停止续传不丢真值、预览版不污染正式版
阶段二 正确性（P3 → P4）      R2 十类缺陷逐一收口、真机现场问题修复
阶段三 表达与收口（P5 → P7）  视觉与动效体系、源连接四态灯、证据账本键归一化
阶段四 发布基线（R1）         可独立编译、行尾可复现、构建脚本可移植、作用域语义正确
```

**关键观察**：Preview.1~3 修的是"数据对不对"（`src/PCMig.Core` 为主）；Preview.4~7 修的是"界面说得对不对"（`src/PCMig.WinUI` 为主）。两类改动叠加在同一批文件上，是核心视图模型文件跨多轮改动的直接原因。

## 2. v0.5.3 → v0.5.4 用户可感知变化

基线：v0.5.3（2026-10-09 发布）。

| # | 变化 | 用户看到什么 |
|---|---|---|
| U1 | 源连接灯不再永久变黄 | 添加共享成功后立即变绿；空闲保持 5 分钟以上仍为绿色常亮（此前约 20 秒内必转黄且不自愈） |
| U2 | 灯色四态语义统一 | 红常亮=未连接；黄呼吸=连接中；绿常亮=已连接/暂停/完成；绿呼吸=传输中 |
| U3 | 顶栏与底栏状态一致 | 不再出现"底栏已黄、顶栏还写已连接"的撕裂 |
| U4 | 进度百分比不再越过 100% | 进度分子与百分比统一由 `ProgressTruthSnapshot` 计算，分子可计上界封顶为计划总量 —— 不再出现真机那种 `completedBytes > totalBytes` 却显示 100% 的情况。⚠ **注意：`/Z` 大文件通道的进度分子仍以进程 I/O 计数器兜底**（否则单个数十 GB 对象在复制期间分子一个字节都不涨），因此 **`completedBytes` 仍存在估算偏差，界面速率不得作为性能数字**（见 2.1 K1） |
| U5 | 停止/续传后进度连续 | 暂停再继续，进度从真实位置接续，不跳变、不清零 |
| U6 | 大对象迁移完成后不卡死 | 存在失败对象时，完成阶段不再出现 UI 线程长时间自旋 |
| U7 | 提示卡可读性与信息图标 | 提示卡文字、图标、无障碍修复 |
| U8 | 窗口自适应各屏幕与 DPI | 高 DPI、多显示器、小屏下布局不再错位 |
| U9 | 验证链与修复隔离 | 修复后自动验证、隔离区记账、报告结论可读 |
| U10 | 沉浸式传输进度 | 传输过程中的视觉呈现升级 |

### 2.1 已知缺陷（v0.5.4 未修复，如实声明）

| # | 缺陷 | 影响 | 为何本版不修 |
|---|---|---|---|
| K1 | `completedBytes` 统计口径混用：`/Z` 大文件通道用进程 I/O 计数器（源端已读字节）与文件数据字节取 `Math.Max` 兜底（`TransferOrchestrator.cs` 内 `ioConfirmed` 分支） | **大文件在途期间进度与速度可能偏高**，真机实测存在数倍偏差；该值仅用于显示，不参与回执与校验 | 若去掉兜底，单个大型对象在复制期间分子完全不动（robocopy stdout 块缓冲 + `/J` 目标预分配 + 回退枚举被禁三者叠加）。修复需改动回执/验证/续传语义，风险高于收益；且需先建立受控性能基线才能证明修复有效 |
| K2 | `bytesPerSecond` 为整段平均而非滑动窗口 | 速率曲线不反映瞬时吞吐 | 同 K1 |
| K3 | 暂停瞬间磁盘侧保留旧速率而界面显示 0 | 暂停瞬间速率显示不一致 | 同 K1 |
| K4 | Bulk/Large 通道错配（≥512MB 文件不进 Bulk，而 Large 通道需等 Bulk 结束才启动） | 大批量传输期间 `/MT` 对大文件不生效 | 需单独设计并以受控数据支撑，不能无依据提高线程数 |

> **不要承诺具体传输速度。** K1–K3 使得界面速率不能作为性能结论的依据；性能结论必须来自 robocopy 与 PCMig 在相同文件集上的受控对照实测。

### 2.2 与 v0.5.3 的兼容性

| 项 | v0.5.3 | v0.5.4 | 兼容 |

## 3. R1 发布基线整改（2026-10-24）

| # | 问题 | 处置 |
|---|---|---|
| R1-A | `HEAD` 提交无法独立编译（缺 `WindowLayoutPlanner.cs`、`SourceStripper.cs`、`UiHarness.cs`、`MainWindow.Harness.cs` 等） | 逐文件归属分类后按逻辑提交补齐，确保每个提交点可编译 |
| R1-B | 无 `.gitattributes`，`core.autocrlf=true` 下行尾不可复现 | 新增 `* text=auto` + 二进制白名单；临时副本四组对照实测确认**零行尾噪声**（否决 `eol=lf` 方案，它会重写 11 个文件的 blob） |
| R1-C | `tools/release.ps1` 硬编码开发机绝对路径 | 全部参数化（`-Repo` / `-Delivery` / `-WorkCopy` / `-Mirror`，支持同名环境变量），并新增四道发布输入闸门：路径、源码完整性、工具链、版本形态与 Git 状态；`-GateOnly` 支持只校验不构建 |
| R1-D | **子路径连接证据作用域缺陷**：共享根事实与子路径事实混用同一账本键，导致"共享根可达 + 子目录不可达"被误判为 Partial 且新旧证据互相抵消 | 证据键折叠到共享根作用域（`\\host\share`），子路径不可读另记独立诊断（同样受 60 秒 TTL 约束、可自愈），共享根可达时不再抹掉子路径诊断、也不误清兄弟路径；黄灯可由 `UnreachableShares` 定位到具体子路径 |

## 5. 未覆盖项（如实）

- 真实 SMB 复杂场景（域环境多共享、凭据冲突、多网卡、真实断链重连）未在研发机上复现，依赖现场真机验收。
- 界面灯色的自动化验证基于研发机注入输入条件的 Harness 实测（真实 XAML + 真实动效 + 真实视图模型投影），**不等于**真机 SMB 验收通过。
- 性能受控 A/B 对照未完成（受目标文件服务器可达性限制），因此本版**不声明任何吞吐改进**。

## 收口：v0.5.4 Stable（2026-10-24）

七轮 Preview 与 RC.1 的全部改动，已随 v0.5.4 正式版收口。正式版只做版本身份、安装身份、更新日志与发布包装调整，不重新设计 UI、连接灯、进度条，也不改迁移业务逻辑与默认参数。

- 正式版安装身份：沿用 v0.5.3 的 AppId、安装目录 {autopf}\PCMig 与数据存放位置（任务库 `%ProgramData%\PCMig\Jobs`、日志 `%ProgramData%\PCMig\Logs`、诊断会话 `%LocalAppData%\PCMig\Diagnostics`）。
- RC.1 的独立安装身份与独立数据位置（PCMig-RC1、%LocalAppData%\PCMig-RC1）不进入正式包。
- 七轮 Preview 属本地研发迭代，未在 GitHub 逐轮正式发布；逐轮真实记录保留在本文件，正式版用户可见的变更摘要见 docs/更新日志.md 与 GitHub v0.5.4 Release。
