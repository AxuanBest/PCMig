## 三、项目是什么

**PCMig** —— 企业内网 Windows 换机数据迁移工具（C#/.NET 8，WPF GUI + CLI，Robocopy 双通道引擎）。
在新电脑运行，输入旧电脑 IP/电脑名 + 凭据，经 SMB 把旧机共享盘数据"直拉"过来。

**功能自 v0.2.28 起冻结**：只做修复、加固、纯视觉层。禁止动 ViewModel / Command / 绑定 / 迁移与 Robocopy 逻辑 / 状态机 / 错误处理 / 网络检测；禁止改存档格式（`job-state.json` 字段语义、`plan.json`、Receipt）。

## 六、⚠ 关键根因知识（新会话最容易重犯的地方）

这一节是本文件最有价值的部分。

### 6.1 隐式 Style 的 ControlTemplate 触发器会压过 TemplateBinding

**这是"实时日志 Hover 爆白"的真正根因**，也是本项目最容易重犯的坑：

`MainWindow.xaml` L175 有一个**隐式** `<Style TargetType="TextBox">`（给表单输入框用的），它的 `ControlTemplate.Triggers` 里有：
```xml
<Trigger Property="IsMouseOver" Value="True">
  <Setter TargetName="bd" Property="Background" Value="{DynamicResource GlassHoverBg}"/>
</Trigger>
```
**`ControlTemplate.Triggers` 的优先级高于 `TemplateBinding Background`。** 所以任何复用这个隐式样式的 TextBox——包括**只读的实时日志**——鼠标一进去，背景就从深色 `GlassLogBg` 被刷成浅色。

**修法**：给日志单独定义 `x:Key="LogViewer"` 只读样式，背景恒定、不参与 Hover 变色。**不要为了修日志去改那个全局隐式样式**（输入框的 Hover 亮起是正常行为，用户明确要求保留）。

**同理**：`Card` 样式是静态 setter，**没有** `IsMouseOver`——排查时别搞错对象。

### 6.2 「同一个视觉区域内，浮雕边缘只由最外层真实 Surface 绘制一次」

反复踩到的"套娃双框"问题：
- 红色报错栏：外层 Surface + `Margin=1` 的 InnerEdge 覆盖层 → 双框
- 实时日志：外层 `GlassContentSurface` + 内层模板里还留着一个 `edge` 描边 Border → 双框

**原则**：内层内容容器**不得重复绘制**同一层 Edge Lighting。日志区域既然已统一为深色内容底，内框就不该再有浮雕描边。

### 6.3 Root Background 被不透明层盖住

`Grid.RowSpan="3"` 的承载层若用 `GlassWashBg`（完全不透明）会盖掉 `Window.Background`，表现为"背景渐变没生效"。

### 6.4 CornerRadius / Double 类型错配会直接崩进程

三套主题里 `RadiusScroll` 曾被写成 `<s:Double>4</s:Double>`，却以 `CornerRadius="{DynamicResource RadiusScroll}"` 使用 → 更新日志窗口的 ListBox 创建 ScrollViewer 应用隐式 ScrollBar 样式时类型转换失败 → **进程崩溃**。三套主题必须同类型。

### 6.5 用户明确禁止过的做法（不要再提）

- ❌ 通过**降低全局 Hover** 来解决局部爆白
- ❌ 推翻当前主题 / 删除已满意的 Edge Lighting / 增强高光到刺眼
- ❌ 增加透明玻璃、Liquid Glass distortion、强 Blur、Refraction、Glass Noise
- ❌ 大面积灰色或纯白 Surface / Neumorphism
- ❌ 改动 Root Background 方向 / 把蓝红橙渐变应用到前景模块
- ❌ 修改已正常的 Update Log
- ❌ "珍珠白 = 高级白" —— 用户要的是 **Soft Tinted Pearl Surface**

## 七、设计不变量（改 UI 前必须遵守）

### 7.1 三套主题必须 key 数一致
`Theme/Glass.xaml`、`Theme/Glass.Dark.xaml`、`Theme/Classic.xaml` —— 发版前是 **152 / 152 / 152，缺 0 多 0**。加/删 Token 必须三家同步。

| Token | 亮色值 | 暗色值 |
|---|---|---|
| `SurfacePearl` | `#F4F7FC` → `#F1F5FA` → `#EDF1F8`（渐变） | `#232833` → `#20252E` → `#1D222A` |
| `GlassLogBg` | `#FF1B2029` | `#FF12161B` |
| `SurfaceColor`（按钮） | `#FFFFFF` | — |
| `AppBackgroundBrush` | `#E3EDFA`→`#E9EBF7`→`#F8E9EC`→`#FBEFE4` | — |
| `Classic.SurfacePearl` | `#F1F3F7`（SolidColorBrush） | — |

**层级契约**：Surface 必须不透明；**按钮（`#FFFFFF`）必须比大型 Surface 更亮**；大型 Surface 不得是 `#FFFFFF`、不得是灰色。

### 7.2 交互实现方式
- Hover / Pressed **只动 `RenderTransform` + `Effect`**，绝不改 Margin/Height/Width/Padding（会引起布局抖动）
- 边缘光影从左上打，保持 45° 读数；边缘恒定 **1px**
- `EdgeHighlightPressed` 把光源原点反向成 `0.94,0.92`
- Elevation 阶梯：`ContactShadow`(Blur 3 / Depth 1.2 / Direction 315) → Elevation1..6；hover = Elevation1，active/selected = Elevation2
- Warning/Error 高光是**带色调的低 alpha 白**（`#7AFFF4EC` / `#7AFFF0EE`），阴影用加深的语义色（`#3DA85F00` / `#3DA82A22`）—— **绝不用纯白，绝不用灰**

## 九、本机工具限制（会浪费大量时间，务必先看）

### 9.1 UI Automation 极不稳定
- 在 `powershell -File` 子进程中 `AutomationElement.FromHandle` **必抛** `ElementNotAvailableException: "Unrecognized error."`
- 即便在主进程内也**间歇性失败** —— 需要**带重试循环**（本次成功方式是重试最多 5 次、每次间隔 1–2 秒）
- **可靠替代**：自己 P/Invoke `EnumWindows` + `GetWindowTextW` + `GetWindowRect` 枚举窗口，再对目标窗口做 UIA 读取
- 通过 `AutomationId`（如 `BtnChangelog`）查找比按 Name 查找可靠

### 9.2 PowerShell 5.1 语法陷阱（已多次踩）
- ❌ **没有三元运算符** `? :`
- ❌ `$_. [0]`（中间带空格）是**解析错误**
- ❌ 脚本里出现 **全角圈号 ①②③④⑤** 会导致 `Unexpected token` 解析失败 —— 用 ASCII 的 `[1]`、`[2]`
- ⚠ 所有 `.ps1` 必须 **UTF-8 带 BOM**，否则中文坏掉

### 9.3 编码与行尾
- `.ps1`：**UTF-8 + BOM**
- XAML：**UTF-8 无 BOM**
- 交付的 `更新日志.txt`：**UTF-8 BOM + CRLF**
- 改文件时用「读字节→检测 BOM→`ReadAllText`→字面替换→按原 BOM 写回」的 `ReplaceExact` 模式，并**检测目标文件是 CRLF 还是 LF**

### 9.4 截图与坐标
- `Snap`/`GetPixel` 类辅助函数**必须做边界检查**，否则窗口移动后会产生大量 `ArgumentOutOfRangeException`
- 窗口原点会变（出现过 `(104,104)`），**不要用固定坐标采样**
