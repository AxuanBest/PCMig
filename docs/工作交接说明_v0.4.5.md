## 一、项目概览

**PCMig**：企业内网 Windows 数据/用户环境迁移工具。直拉模式（Direct Pull）——在新电脑运行，输入旧电脑 IP/电脑名 + 凭据，通过 SMB 把旧电脑共享盘数据完整拉到新电脑。

- **技术栈**：C# / .NET 8（WPF GUI + CLI）、Robocopy 传输引擎、Serilog 三层日志、Inno Setup 安装包、YAML 策略矩阵
- **核心机制**：
  - Data Plane（D 盘全量）/ State Plane（C 盘 Profile+Recipe）分治
  - 双通道 Robocopy（批量 `/MT` + 大文件通道）；网络路径才加 `/J`
  - 对象级调度；Receipt 只追加回执为权威状态（`job-state.json` 仅是视图，损坏可由回执重建）
  - 协作式暂停；三级进度；L1 数量字节比对 / L2 抽样哈希
- **安全边界（V1 明确不做）**：凭据/Cookie（DPAPI 绑定源机）、驱动、安全软件、整盘 ACL、Windows 系统目录 → 见 `matrix\migration-matrix.yaml` 的 `securityBlockedFileNames`
- **路线图**：V1.5 Outlook/浏览器 Recipe、OneDrive KFM、零安装远程采集；V2.0 Win7 源兼容、winget 编排、GUI 多任务视图。**功能冻结解除前不主动开工。**
- **已知限制（如实记录，非 bug 未改）**：断点续传只到**对象级**，被中断的大文件从头重传（`/Z` 预分配全尺寸所致）

**contextWindow 变更说明（2026-09-19 由本会话实施）**：
- 原因：DSH 的 `dsh-llm-pi-ai` provider（百炼走这个）默认 `DEFAULT_CONTEXT_WINDOW = 262144`（256K），而模型本身支持 1M。
- 改法：在 `settings.yaml` 的模型条目上加最高优先级覆盖（依据 `dsh-llm-pi-ai/lib/index.js:670` 的 `entry.contextWindow ?? base?.contextWindow ?? request.defaultContextWindow`）：
  ```yaml
        - id: deepseek-v4.1-flash
          name: deepseek-v4.1-flash
          contextWindow: 1000000
  ```
- 已验证：YAML 解析通过，`effective contextWindow = 1000000`，其余 8 个配置段（`dsh-desktop`、`dsh-desktop-notifications`、`ui-onboarding`、`dsh-community-market`、`llm-pi-ai`、`agent-default-model`、`dsh-neu-theme`、`vision-toolkit`）全部保留。
- **需重启 DSH Desktop 并新建会话才生效**（`contextWindow` 在构建请求时读取，当前会话仍是旧值）。
- 参考：该模型官方支持 1M；但实测经验上 **150–250k 是编码任务的最佳区间**，1M 是"不被强制压缩"的保险，不是"应该塞满"的目标。

## 七、⚠ 关键根因知识（新会话最容易重犯）

> 这一节是本文件最有价值的部分。

### 7.1 隐式 Style 的 `ControlTemplate.Triggers` 会压过 `TemplateBinding`

**这是"实时日志 Hover 爆白"的真正根因**，也是本项目最容易重犯的坑：

`MainWindow.xaml` L175 有一个**隐式** `<Style TargetType="TextBox">`（给表单输入框用的），它的 `ControlTemplate.Triggers` 里有：
```xml
<Trigger Property="IsMouseOver" Value="True">
  <Setter TargetName="bd" Property="Background" Value="{DynamicResource GlassHoverBg}"/>
</Trigger>
```
**`ControlTemplate.Triggers` 的优先级高于 `TemplateBinding Background`。** 所以任何复用这个隐式样式的 TextBox——包括**只读的实时日志**——鼠标一进去，背景就从深色 `GlassLogBg` 被刷成浅色。

**修法**：给日志单独定义 `x:Key="LogViewer"` 只读样式（背景恒定、`Padding=0`、模板只有 `bd` + `PART_ContentHost`、无 `IsMouseOver`、无 `ControlTemplate.Triggers`）。**不要为了修日志去改那个全局隐式样式**——输入框的 Hover 亮起是正常行为，用户明确要求保留。

**同理**：`Card` 样式是静态 setter，**没有** `IsMouseOver`——排查时别搞错对象（我一度把它当嫌疑犯）。

**证据**：用户截图 1096×237 中 L≥250 占 70.8%，y=36..210 整片纯白；同一容器内标题行为 L<120 深色、TextBox 区为 L≥252 纯白 → 证明只有 TextBox 响应 Hover。修复后截图 1036×209 全程 L=32（= `GlassLogBg` 亮度）。

### 7.2 「同一视觉区域内，浮雕边缘只由最外层真实 Surface 绘制一次」

反复踩到的"套娃双框"问题：
- 红色报错栏：外层 Surface + `Margin=1` 的 InnerEdge 覆盖层 → 双框
- 实时日志：外层 `GlassContentSurface` + 内层模板里还留着一个 `edge` 描边 Border → 双框

**原则**：内层内容容器**不得重复绘制**同一层 Edge Lighting。日志区域既然已统一为深色内容底，内框就不该再有浮雕描边。

### 7.3 Root Background 被不透明层盖住

`Grid.RowSpan="3"` 的承载层若用 `GlassWashBg`（完全不透明）会盖掉 `Window.Background`，表现为"背景渐变没生效"。
**证据**：修复后窗口左上 RGB(238,245,249) 偏蓝、右缘 RGB(250,237,231) 偏暖；全窗色相分布 蓝 61.9% / 暖 15.9% / 中性 22.3%。

### 7.4 「透明 Surface」是自伤，不是设计

上一轮曾为让 Root Background 透出，把三处 `Background` 从 `GlassRailBg` 改成 `Transparent` → 结果是"只有一个浮雕边框框住了一块背景"。**修法是引入不透明的 `SurfacePearl`，而不是靠透明。**

### 7.5 `CornerRadius` / `Double` 类型错配会直接崩进程

三套主题里 `RadiusScroll` 曾被写成 `<s:Double>4</s:Double>`，却以 `CornerRadius="{DynamicResource RadiusScroll}"` 使用 → 更新日志窗口的 ListBox 创建 ScrollViewer、应用隐式 ScrollBar 样式时类型转换失败 → **进程崩溃**。三套主题必须同类型、同 key 数。

### 7.6 用户明确禁止过的做法（不要再提）

- ❌ 通过**降低全局 Hover** 来解决局部爆白
- ❌ 推翻当前主题 / 删除已满意的 Edge Lighting / 增强高光到刺眼
- ❌ 增加透明玻璃、Liquid Glass distortion、强 Blur、Refraction、Distortion、Glass Noise
- ❌ 大面积灰色或纯白 Surface / Neumorphism / 老式 3D Button / Windows7 Aero
- ❌ 改动 Root Background 方向 / 把蓝红橙渐变应用到前景模块
- ❌ 修改已正常的 Update Log
- ❌ 把「珍珠白」理解成「高级白」——用户要的是 **Soft Tinted Pearl Surface**
- ❌ 内容 Surface 加 Button 级 Hover

### 8.2 层级契约

```
Layer 0  Root Background    浅蓝 → 浅红 → 浅橙 环境渐变（最底层，不染色上层）
Layer 1  Opaque Surface     SurfacePearl，不透明、非纯白、非灰
Layer 2  Edge Lighting      1px 极细边缘高光，统一左上→右下约 45°
Layer 3  Hover / Pressed    只动 RenderTransform + Effect
```

**硬性要求**：Surface **必须不透明**；**按钮（`#FFFFFF`）必须比大型 Surface 更亮**；大型 Surface 不得是 `#FFFFFF`、不得是灰色；同一视觉区域内浮雕边缘只画一次。

### 8.3 交互实现方式

- Hover / Pressed **只动 `RenderTransform` + `Effect`**，绝不改 `Margin`/`Height`/`Width`/`Padding`（会引起布局抖动）
- 边缘光影从左上打，保持 45° 读数（径向边缘刷保证任意宽高比下都是 45°）；边缘恒定 **1px**
- `EdgeHighlightPressed` 把光源原点反向成 `0.94,0.92`
- Elevation 阶梯：`ContactShadow`(Blur 3 / Depth 1.2 / Direction 315) → Elevation1..6；**hover = Elevation1，active/selected = Elevation2**
- Warning/Error 高光是**带色调的低 alpha 白**（`#7AFFF4EC` / `#7AFFF0EE`），阴影用加深的语义色（`#3DA85F00` / `#3DA82A22`）—— **绝不用纯白，绝不用灰**

### 8.4 其他硬性约束

- 四个导航项必须都能切换页面；Selected 状态不得使用大面积蓝色块
- Update 按钮不得是纯蓝方块
- XAML 隐式 Style **只改不新建**（`Item has already been added` 坑）
- Property Element（如 `Grid.RowDefinitions`）位置必须合法（MC3088）

## 十一、本机工具限制（会浪费大量时间，务必先看）

### 11.1 UI Automation 极不稳定

- 在 `powershell -File` 子进程中 `AutomationElement.FromHandle` **必抛** `ElementNotAvailableException: "Unrecognized error."`
- 即便在主进程内也**间歇性失败** —— 需要**带重试循环**（本次成功方式：重试最多 5 次、每次间隔 1–2 秒）
- **可靠替代**：自己 P/Invoke `EnumWindows` + `GetWindowThreadProcessId` + `GetWindowTextW` + `GetWindowRect` 枚举窗口，再对目标窗口句柄做 UIA 读取
- 通过 `AutomationId`（如 `BtnChangelog`）查找比按 `Name` 查找可靠
- 曾尝试「按图像启发式自动发现导航项」彻底失败（只检测到 2 个伪条带，点击从未到达第 4 页）

### 11.2 PowerShell 5.1 语法陷阱（已多次踩）

- ❌ **没有三元运算符** `? :`
- ❌ `$_. [0]`（中间带空格）是**解析错误**
- ❌ 脚本里出现 **全角圈号 ①②③④⑤** 会导致 `Unexpected token` 解析失败 —— 用 ASCII 的 `[1]`、`[2]`
- ⚠ `.NET` 文件 API（`[IO.File]::ReadAllBytes`）用**进程当前目录**，**不跟随 PowerShell 的 `Set-Location`** —— 必须传绝对路径（本会话踩过两次）
- ⚠ `git rev-parse <tag>` 返回的是**注释 tag 对象**的 SHA，不是 commit SHA；要 commit 用 `git rev-parse <tag>^{commit}` 或 `git rev-list -n 1 <tag>`
- ⚠ Node 的 `zlib.zstdDecompressSync` **只解第一个 zstd 帧**；DSH 的 `session.v3.jsonl.zstd` 是**多帧拼接**，需按 magic `28 B5 2F FD` 分帧后逐帧解压（1293 帧可全部解出）

### 11.3 编码与行尾

- `.ps1`：**UTF-8 + BOM**
- XAML：**UTF-8 无 BOM**
- 交付的 `更新日志.txt`：**UTF-8 BOM + CRLF**
- `docs\*.md`：UTF-8 **无 BOM**（与本仓库现状一致）
- 改文件用「读字节 → 检测 BOM → `ReadAllText` → 字面替换 → 按原 BOM 写回」的 `ReplaceExact` 模式，并**检测目标文件是 CRLF 还是 LF** 后统一插入内容的行尾
- ⚠ **不要用 edit 类工具改 `.ps1`**：实测会**丢失 UTF-8 BOM**（本次改 `release.ps1` 后前 3 字节变成 `23 20 50` = `# P`）。改 `.ps1` 请用 PowerShell 的 `ReplaceExact` 模式，或改完**立即复查前 3 字节是否为 `EF BB BF`** 并补回
- 插入表格行/段落时，**别忘了补换行符**（本会话踩过两次，导致新行与旧行黏连）

### 11.4 截图与坐标

- `Snap`/`GetPixel` 类辅助函数**必须做边界检查**
- 窗口原点会变（出现过 `(104,104)`），**不要用固定坐标采样**
