## 2. 设计依据：把历史"三套"做法辨清（这是本轮最关键的一次更正）

用户第 22 节要求"不要凭感觉重新发明，去查 Git 历史 / 旧版 Resource / SurfacePearl / Archive"。
**只读调研（子代理）得到的结论推翻了此前交接文档的一个机制论断**：

| # | 做法 | 载体 | 类型 | 用户裁定 |
|---|---|---|---|---|
| (i) | 老版 WPF `EdgeHighlight` | `Border.BorderBrush` + `BorderThickness=1` | **`RadialGradientBrush`**（径向） | ✅ **成功**，用户点名复用 |
| (ii-a) | WinUI 某轮 `EdgeHighlightDiagonalBrush` / `EdgeHighlightCrispBrush` | `Border.BorderBrush` | **`LinearGradientBrush`**（线性） | ❌「粗白边 / 一圈白描边 / 框出来」 |
| (ii-b) | WinUI 另一轮 `PCMigDirectionalLightBrush` + 四条独立边线 | `Background` 面填充 + 边线 | 线性 + 固定暗色 | ❌「灰黑脏阴影」+ 重大回归事故 |

**★ 机制更正（此前 A32 注释的说法是不完整的）**：
> `Materials.xaml` A32 注释断言「高光不能写在 BorderBrush 上，因为会沿整圈四边描一遍」。
> **该论断只对线性渐变成立**。在**径向**渐变场里，1 DIP 描边环各点取到的颜色天然随位置连续变化
> （左上段亮白 → 右下段深色），因此**一个渐变环可以同时表达「左上高光 + 右下暗边」，且四边不等强**。

**git 铁证**（只读查询）：`src/PCMig.Gui/Theme/Glass.xaml` 的 `EdgeHighlight` 类型随提交改变 ——
提交 `1c0fdef`（UI 重构 v0.4.2）是 `LinearGradientBrush`；提交 **`712e88c`（提交信息即「45° 斜向光源修正」）
改成了 `RadialGradientBrush GradientOrigin/Center="0.06,0.08" RadiusX/Y=1.25`**，此后到 HEAD 未再变。
⇒ **"45° 光源修正"的实质就是把线性改成径向**，这就是被用户判定成功的那一版。

**"灰黑脏阴影"的真正来源**已确认（`工作交接-20260928-...md:89` 逐字）：
`PCMigDirectionalLightBrush` 的 `#2A0D1A2C` 与 `PCMigEdgeShadeBrush` 的 `#32233A5E` 这类
**大面积暗色面填充**。本会话**完全没有使用任何暗色面填充**，暗部只由径向渐变自身深色端承担。

### 3.3 高光档位的实测标定过程（**下一任必读，避免重复踩坑**）

第一版用旧版原值 `#33FFFFFF(20% 白)` 作左上端点，实测：

> 「边缘像素 − 向内 4px 参照像素」的差分 = **左上仅 +1.0 亮度单位**，视觉复核明确"看不到高光"。

**根因是物理上限，不是参数取值问题**：
`白高光增益 ≈ alpha × (255 − 卡面亮度)`。卡片在 Card Material **50/80** 档时卡面已达
240~253，白高光理论上限只有 +2…+15，**完全没有余量**。
⇒ 结论：**高光只能在低材质档发力；高材质档的轮廓必须由右下蓝灰暗边承担**（这正是用户第 14 节
"不得与 Material 1:1 同步"的正确落地方式，也是本设计"两者互补"的由来）。
故把左上端点提到 `#66FFFFFF(40%)`，实测左上差分抬到 **+8.5（20 档）**，而**厚度仍是 1 DIP**。

## 8. 环境与工具的关键事实（**下一任必读，本会话新发现**）

1. **`pwsh` 调用结束后，它拉起的 GUI 进程会被一并回收。**

   且**事件日志无崩溃、WER 无转储** ⇒ 不是崩溃，是进程树回收。
   **后果**：`验证台`脚本必须把「启动 → UIA 驱动 → 截图 → 测量」全部放在**同一次 pwsh 调用**内。
   本会话已按此重写 `archive\scripts\a41-stepcard-light-verify.ps1`。
2. **MSBuild 多节点并行（`-m`）在本沙箱下必然失败**：`dotnet build PCMig.sln` 报
   "生成失败 / 0 警告 0 错误"（仅 2 秒），而**四个项目单独构建全部成功**。
   加 **`-m:1` 后解决方案构建 0 警告 0 错误**。⇒ 交接给下一任：**解决方案级构建一律加 `-m:1`**。
