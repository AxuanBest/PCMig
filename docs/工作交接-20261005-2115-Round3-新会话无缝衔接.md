## 2. 本轮改了什么（按层，全部未提交）

### A. Core 真值（P0 根因修复）
文件：`src\PCMig.Core\Transfer\TransferOrchestrator.cs`（唯一改动的 Core 文件）

- `MarkInterrupted(ObjectReceipt receipt, PlannedObject obj, long trustedObjectConfirmedBytes, long trustedAttemptEpoch)`：**不再测目标长度**；`receipt.TargetBytes` 语义 = 「截至打断时刻的可信已确认字节」。两个调用点都在 `ResolveLiveTrustedObjectBytes(obj)` 与 `_lastTrustedAttemptEpoch`。
- `ResolveResumeBaselineForPass(pass, measuredTargetBytes, trustedReceiptBytes, objectMayPreallocate)`：可信回执优先；**预分配对象永不采信目标长度**；只有纯 Bulk（且对象不预分配）才允许把实测长度当兜底（保住"Pause 后不假归零"）。
- `ResolveTrustedInterruptedBytes(IEnumerable<ObjectReceipt> receipts, string objectId, long plannedBytes)`：**顺序无关**——按「最新一次尝试的状态（先 `CompletedUtc`、同刻比 `Attempt`）+ 所有 Interrupted 回执的**最大值**」解析，再按计划夹取。真机日志已出现「共有 2/3/4 份回执…」。
- `ResolveLiveTrustedObjectBytes(obj)`：**只有 `_currentPass == PassKind.Bulk`** 才允许 `MeasureCurrentTargetBytes(obj)` 当补充证据（否则 Pause 会回退成 UI-02 的假 0 B）；Large(`/Z`、`/J`) 通道禁止。
- `MeasureTarget` → **`MeasureSettledTarget`**（名字即纪律：只有已落定 Completed / 可实测失败收尾 / Verifier 才可调用）。
- `/Z` 大文件失败**入账回冲**：`_largeCredited` + `OnRunnerErrorLine` 里 `Interlocked.Add(ref _largeCompletedBytes, -creditedLarge)`。
- `TraceProgressSnapshot(...)` 输出 `ProgressTrace#N`（受 `PCMIG_PROGRESS_TRACE=1` 控制，写 **job 日志**）。

## 6. 踩坑清单（先读，能省你两小时）

1. **不受检的截图/ROI 会产出假数据**：本机 `SetForegroundWindow` / `SetWindowPos(HWND_TOPMOST)` / `PrintWindow` 全拿不到 WinUI 3 真实画面（窗口状态全正常，读到的却是浏览器）。唯一可靠路径 = `New-Object -ComObject Shell.Application; $shell.MinimizeAll()` 后恢复目标窗口，且脚本必须带 `SELFCHECK maxLuma` 自检（探针页中心应为 `#0B0E13`，luma 14）。
2. **窗口原点每次启动都变**（见过 `26,26` / `104,104` / `208,208` / `234,234` / `182,182`，尺寸 1440x900）。**屏幕像素归因必须用同一次运行的 UIA 原点**——我曾因套用上一轮原点误判"轨道渲染成浅灰蓝"，实测轨道 `#28446A`@α=0x6C 叠在页面 `#0B0E13` ⇒ `#172538`，与屏上 `#172333` 一致；不透明填充 `#368BF8` 与屏上逐字节相同 ⇒ 控件画的就是设计色。
3. **`ensure-step3.ps1` / `capture-progress-frames.ps1` 本轮已修**：旧 `TotalProgressHost` 已不在 UIA 树里（新控件是 `ControlType.ProgressBar`、aid `TotalImmersiveProgress`）；`capture-progress-frames.ps1` 原来会按名字前缀**静默选中底栏 138×8 轻量条**（那份 `frames.csv` 记的是错对象）。现在锚点不明直接报错退出，并强制 `RoiW >= 400` 与在屏检查。
4. **`RenderTargetBitmap` 与 `Translation` 不兼容**（`ArgumentException: … Context: Translation …`）⇒ 应用内导出生产卡片 PNG 不可行；生产卡像素证据靠探针的同风格区块。
5. **同源判据的正确口径**：`headX ≈ visualPercent% × hostWidth(1010)`（`headX` 与 `progressWidth` 按构造恒等；拿 `visualPercent% × progressWidth` 去比会得到成百行假警报）。`pw/headX` 来自**最后绘制帧**、`visualPercent` 是写入时刻的协调器值 ⇒ **允许落后一帧**。
6. **粒子越界判据要单列 `progressWidth = 0` 的行**（0% 时没有填充胶囊）——已修：无胶囊时活跃粒子数为 0。
7. **PowerShell 老坑**：`$host` 是**只读自动变量**（当数值用会把脚本刷成一片报错并污染统计，改用 `$hostW`）；pwsh 里 `Set-Location` 后 `[IO.File]::ReadAllText('相对路径')` 仍按**进程 CWD** 解析 ⇒ 文件 API 一律绝对路径；中文 `.ps1` 必须 UTF-8 **带 BOM**（`[IO.File]::WriteAllText($p,$t,[Text.UTF8Encoding]::new($true))`，`Set-Content -Encoding UTF8` 在 pwsh 里**不写 BOM**）；`uia-lib.ps1` 的 `Invoke-RgClick` 参数是「元素, 点击次数」**不是 aid 名**；`ScrollPattern.Scroll()` 在 5.1 报错（用 `SetScrollPercent`）；`(…).Count` 在单命中时为 `$null`（用 `@(…).Count`）。
8. **Win2D 没有托管参考程序集**，API 形状只能靠编译器错误确证：`Stops` 是只读属性但**索引器可写**、其 `Count` 是**方法组**、`DrawCircle` **无**弧线重载、`AddArc` **只有**「终点+半径+旋转+`CanvasSweepDirection`+`CanvasArcSize`」、`Colors` 属 **`Microsoft.UI`**、WinUI 3 `IRangeValueProvider` **无** `RangeValueChanged`。
9. **断言不许命中自己的注释**：`Assert.DoesNotContain("TotalProgressFill", …)` 会被方法名 `UpdateTotalProgressFill` 命中 ⇒ 按"元素用法"（`TotalProgressFill.` / `(TotalProgressFill,`）断言，或先改写注释。
10. **本机吞吐 2.7~5 GB/s**：42 GB 任务约 4~10 s 跑完，中间态窗口很窄 ⇒ 中间态必须用**时间触发**（如 `-PauseAfterSec 1.5`），不能等百分比；`E:` 空间耗尽会让每个文件都失败而 UI 仍在入账——那是**夹具**问题，不是产品缺陷。
