## 4. MainViewModel 耦合审计（结论）

`MainViewModel.cs`（2058 行）**不可直接复用到 WinUI**。耦合面窄但可枚举：
- WPF `using`：`System.Windows` / `.Controls` / `.Media`（8–10 行）
- WPF 类型公共属性：`PointCollection NicSparkPoints`（106）、`System.Windows.Visibility` ×2（273、277）
- `DispatcherTimer` ×2（93、118）、`Application.Current.Dispatcher` 封送 12 处
- 口令经控件实例穿透：`p as PasswordBox`（129、132、620）
- 同步 `AppDialog.Show` + `MessageBoxResult` 5 处（含 1 处默认 `No` 的扫描残缺闸门）
- `Microsoft.Win32.OpenFolderDialog`（662，同步）
- `CommandManager`（Helpers.cs 63–64、82，WPF 专有）

**决策：新增 `PCMig.WinUI` 专用 Presentation Adapter，不复用 MainViewModel、不给 WPF 类型打 shim。**
理由：既有 4 个契约测试按字节读取 `MainViewModel.cs` / `MainWindow.xaml`；shim 下 `p as PasswordBox` 恒为 null，会导致口令静默为空、看似连上实际未建 SMB 会话（本项目已被同类"编译过、运行静默失效"缺陷伤过）。

**长期收敛（属 Phase 2，需单独授权）**：抽 `IDispatcher / IDialogService / IPasswordSource / IPathPicker` 后用 `<Compile Include>` 共享单份 VM 源。

## 7. 本轮踩到并解决的两个真实缺陷（务必带走）

1. **`Icon="BulletedList"` 非法**：`NavigationViewItem.Icon` 只接受 `Symbol` 枚举；非法值在**运行时**抛 `XamlParseException`（编译期不报）。正确值 `List`。
2. **self-contained publish 丢失应用 `.pri`**：发布版启动即 `XamlParseException: XAML parsing failed`，而 `bin` 目录正常。已在 csproj 内固化修复目标 `PcmigWinUICopyAppPriToPublish`（`AfterTargets="Publish"` 复制 `$(TargetDir)$(TargetName).pri`）。
   另：`AcrylicBrush` 的 `BackgroundSource` 是 UWP 专有属性，WinUI 3 用 `TintColor/TintOpacity/FallbackColor`。

## 8. 技术风险（未验证项，不得当成通过）

1. **Windows App SDK 2.5.1 体积**：self-contained 发布目录 **523 文件 / 220.7 MB**，远超现 WPF 单文件 exe；**不能直接进现有交付四件套**，需单独发布策略决策。
2. **NuGet 大包在企业网络下极易断流**：本次靠 BITS + 手工注入缓存才通过；后续 CI/换机需预案（离线包目录）。
3. **WinUI 3 缺少 WPF 的 `DataTrigger` / `EventSetter` / `RelativeSource AncestorType` / `DataGrid`**：静态阅读结论，**本机未逐条实测**；决定四页能否"翻译"还是必须重画，应从 Step 1 起逐个验证。
4. **DPI 多档位 / 跨显示器 / 高对比度 / 关闭透明效果 / RDP** 均未验证。
5. **`vswhere` 工作负载精确查询返回空**：模板存在且构建可用，但注册口径未确认。
6. **Developer Mode 未确认开启**：unpackaged 不依赖，但后续若引入 MSIX 调试需先开。
7. PoC 未做 Core 侧适配器（本轮刻意不做），**尚未验证 13 命令 + 93 绑定根在 WinUI 的完整映射**。
