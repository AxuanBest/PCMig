# 技术发现 — 20260927 — 最小窗口尺寸实现缺陷：边框未计入，客户区比设计下限小

> 性质：**实测确认的实现缺陷**（不是猜测）。按 AGENTS.md 三点五，**本轮只报告，未改源码**。

---

## 一、设计意图 vs 实际行为

| | 值 |
|---|---|
| 设计声明（`MainWindow` 常量名） | `MinimumClientWidthDip = 960` / `MinimumClientHeightDip = 640` |
| 代码注释（`WindowMinimumSize.cs:8`） | 「把 ptMinTrackSize 抬到**设计下限**」 |
| **实测 `ptMinTrackSize`** | **960 × 640** |
| **实测实际客户区** | **944 × 632** |
| **偏差** | **宽 −16，高 −8** |

## 二、根因

`Presentation\WindowMinimumSize.cs:23-31`：

```csharp
public static void Install(IntPtr hwnd, double minWidthDip, double minHeightDip, double scale)
{
    _minWidthPx  = Math.Max(1, (int)Math.Round(minWidthDip  * s));   // 入参是**客户区** DIP
    _minHeightPx = Math.Max(1, (int)Math.Round(minHeightDip * s));
    ...
}
```

第 40-41 行把这两个值**直接写进 `ptMinTrackSize`**：

```csharp
if (mmi.MinTrackSize.X < _minWidthPx)  mmi.MinTrackSize.X  = _minWidthPx;
if (mmi.MinTrackSize.Y < _minHeightPx) mmi.MinTrackSize.Y = _minHeightPx;
```

但 **`MINMAXINFO.ptMinTrackSize` 是"整个窗口外框尺寸"，不是客户区尺寸**。
于是外框被限制成 960×640，客户区就只剩 `960−水平边框` × `640−垂直边框`。

名字叫 `MinimumClientWidthDip`（客户区），语义与用法不一致 —— **这是同一份代码内部的口径矛盾**。

## 三、边框实测值（4 个尺寸交叉验证，完全一致）

| 请求窗口尺寸 | 实际窗口 | 实际客户区 | 水平边框合计 | 垂直边框合计 |
|---|---|---|---|---|
| 960×640（被最小尺寸钳住） | 960×640 | **944×632** | 16（左 8 / 右 8） | 8（上 0 / 下 8） |
| 1000×700 | 1000×700 | 984×692 | 16 | 8 |
| 1200×800 | 1200×800 | 1184×792 | 16 | 8 |
| 1440×900（Canonical） | 1440×900 | 1424×892 | 16 | 8 |

边框在所有尺寸下恒定：**水平 16 DIP、垂直 8 DIP**（上边框 0，因为标题栏是自绘的客户区内容）。

## 四、最小尺寸约束本身**确实生效**（这部分是好的）

强行 `SetWindowPos` 到更小尺寸，两次都被钳回：

| 请求 | 结果 |
|---|---|
| 700×500 | 被钳到 **960×640** ✅ |
| 900×560 | 被钳到 **960×640** ✅ |

⇒ `WM_GETMINMAXINFO` 子类过程工作正常；问题只在**数值口径**上。

## 五、影响评估

- 客户区 944 DIP 落在 **Compact 档**（`MinimumClientWidth=960`，Compact 上限 1120），
  ⇒ **不会掉出档位**，布局逻辑仍成立，没有崩溃或错位风险。
- 影响是**设计承诺没被完整兑现**：声明"最小客户区 960×640"，实际给了 944×632。
- 风险等级：**低**（不破坏布局），但属**容易被忽略的一致性缺陷**。

## 六、建议修法（两选一，未实施）

**方案 A（推荐，最小改动）**：把边框算进去。

```csharp
// Install 内：把"客户区下限"换算成"外框下限"
var frameX = GetSystemMetrics(SM_CXSIZEFRAME) * 2 + GetSystemMetrics(SM_CXPADDEDBORDER) * 2;
var frameY = GetSystemMetrics(SM_CYSIZEFRAME) * 2 + GetSystemMetrics(SM_CYCAPTION);
_minWidthPx  = Math.Max(1, (int)Math.Round(minWidthDip  * s) + frameX);
_minHeightPx = Math.Max(1, (int)Math.Round(minHeightDip * s) + frameY);
```

需 `[DllImport("user32.dll")] static extern int GetSystemMetrics(int nIndex);`，
常量 `SM_CXSIZEFRAME=32` / `SM_CXPADDEDBORDER=92` / `SM_CYSIZEFRAME=33` / `SM_CYCAPTION=4`。

> ⚠️ 注意：本窗口标题栏是**自绘进客户区**的（实测上边框 0），所以 `SM_CYCAPTION` 要**不要加**必须实测确认 ——
> 从本次实测看，垂直边框合计只有 8，说明**没有系统标题栏**，加 `SM_CYCAPTION` 会**多加约 23 DIP**。
> **建议直接实测 `GetWindowRect − GetClientRect` 得到 frameX/frameY，而不是靠 SM_* 常数推算。**

**方案 B（最简单、最稳）**：安装子类后，实测一次 `windowRect − clientRect` 存成常量偏移，
在 `WM_GETMINMAXINFO` 里用 `_minClientPx + offset`。这与方案 A 同思路，但**不依赖任何系统度量常数**。

**验证方法**（修完后照此验收）：
1. `SetWindowPos` 到 700×500，读回窗口矩形应为 **976×648**；
2. 同时读回 `GetClientRect` 应为 **960×640**（= 声明的客户区下限）；
3. 在 125% / 150% 下重复，客户区换算回 DIP 仍应为 960×640。
