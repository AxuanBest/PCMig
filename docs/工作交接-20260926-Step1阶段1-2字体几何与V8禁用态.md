## 2. 本会话确立的关键环境事实（**下一位接手者务必先读，省掉重复踩坑**）

### 2.1 视觉判断通道（最关键的一条）

- 本会话模型为**纯文本模型**：read_image 对截图直接报 model "deepseek-v4.1-flash" does not declare image input；子模型同模型，同样看不到图。
- describe_image 工具在本机**不可用**：报 describe-image: baseURL must be an absolute http(s) URL（未配置视觉端点）。
- 因此本会话的「视觉判断」实际建立在**确定性测量**四件套上：
    1. **Windows OCR 转录**（Windows.Media.Ocr，zh-Hans-CN）→ 每个文字行的墨迹盒 y / x / h，可比对参考图与实现的文字位置与字号；
    2. **像素 / 颜色度量**（System.Drawing + LockBits 内嵌 C#）→ 均色、量化直方图 top-N、N×N 网格均色、任意矩形均值；
    3. **亮度带剖面**（逐行 / 逐列平均亮度与跳变检测）→ 卡片边界、顶边高光线；
    4. **UIA 精确控件几何** → 控件盒 rect / IsEnabled / ControlType。
- **结论**：几何、文字内容与位置、颜色、对比度可以客观收敛；**「整体是否已是同一套视觉语言」这类纯观感判断，本会话无法替代人眼**，最终必须由用户或带视觉的会话认定。

### 2.4 工具链陷阱（本会话逐个踩到并已解决）

| 陷阱 | 现象 | 解法 |
|---|---|---|
| DSH edit 工具**剥掉 UTF-8 BOM** | 改完 .ps1 / XAML 前三字节从 EF BB BF 变 3C … | 改完必须复查并补 BOM（本会话已补 2 个 .ps1，XAML 也统一补回） |

| ConvertFrom-Json 顶层数组 | PS 5.1 下 @(…) 只得到 **1 个元素**（属性变成数组） | 改为 ConvertFrom-Json -InputObject 原文 后接 | ForEach-Object { $_ } 才展开 |
| h 是 Get-History 的**别名，优先级高于函数** | 自定义 function H 被遮蔽，报 Cannot bind parameter 'Id' | 辅助函数不要叫 H（本会话已改名 Enc） |
| $host 是 PowerShell **自动变量** | 函数参数名用 $host → 判断永远为真、逻辑走错分支 | 参数改名（本会话已改 $hostText） |
| Color.R / G / B 是 **Byte**，-shl / -shr 保留 Byte 并按 256 取模 | 量化直方图静默算错（2 -shl 10 得 0） | 转 [int] 或用算术除法 + 字符串键 |
| 纯 PowerShell 逐像素 GetPixel | 1782×1116 直接超时 | 计算放进 Add-Type 内嵌 C#，用 LockBits 扫内存（26ms） |

### 2.5 一个**必须知道的负面发现**：UIA 文本注入会让程序崩溃

- 为拍「启用态主按钮」，本会话给截图脚本加了 -SetHostText（用 UIA ValuePattern.SetValue 往 IP 框写文本）。
- 结果：程序 **3 次 APPCRASH**（15:38:36 / 15:39:20 / 15:40:06）。事件日志：出错应用程序 PCMig.WinUI.exe，出错模块 Microsoft.UI.Xaml.dll 3.2.3.0，异常代码 0xc000027b，错误偏移 0x3a9dbd，HRESULT 0x80070057 (E_INVALIDARG)。
- 对照实验：**不注入**时连续 2 次截图，程序 ALIVE=True、崩溃计数 **0**；单独启动闲置 8s / 3s 再杀，崩溃计数 **0**。
- 结论：**应用本身稳定，注入探针不安全**；该探针**已弃用**，启用态不提供运行证据（本交接如实标注）。
- 教训：任何「为了让某个状态可拍」而向被测程序注入状态的探针，**必须先做崩溃计数对照**（启动 → 操作 → 击杀，查 WER 计数），否则会污染证据链。
