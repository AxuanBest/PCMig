## 一、被纠正的结论

**此前结论（不完整）**：
> "本机没有视频编码器（`ffmpeg` / `magick` / `gifski` 均不存在），所以**无法产出 mp4/gif**，§47 视频验收是硬阻塞。"

**这条结论只查了 `PATH`**（`Get-Command ffmpeg/magick/gifski` + 几个常见安装目录），
因此**漏掉了 Windows 自带的编码能力**。真实情况：

| 事实 | 实测结果 |
|---|---|
| `C:\Windows\System32\mfh264enc.dll` | **存在** |
| `C:\Windows\System32\mfh263enc.dll` | **存在** |
| `C:\Windows\System32\msmpeg2enc.dll` | **存在** |
| `mfplat.dll` / `mfreadwrite.dll` | **存在** |
| `MFTEnumEx` 枚举视频编码器类别 | **返回 7 个编码器**（hr=0x00000000） |
| `MFCreateSinkWriterFromURL` 所需接口 | 可用 |

⇒ **Windows Media Foundation 自带 H.264 编码器**，理论上**不需要安装任何软件、不修改任何系统状态**
就能把 PNG 帧序列编成真正可播放的 MP4。**§47 不是"无解的硬阻塞"，而是"没做出来的工程任务"。**

网络连通性也复核过：`https://aka.ms` HEAD 返回 **HTTP 200**（通），
所以"装 ffmpeg"在技术上也可行 —— 但那属于**新增第三方软件**，需用户单独授权，**本轮未做**。

## 二、正确结论应当怎么写

- ❌ 错：`本机无法产出视频。`
- ✅ 对：`本机 PATH 上没有第三方编码器；Windows 内置 MF H.264 编码器存在，用它编码需要写 COM 互操作代码。`

**教训（可复用）**：判断"本机有没有某种能力"时，**只查 PATH 是不够的**。
要同时查：PATH、系统目录 DLL、系统 API 枚举（本例的 `MFTEnumEx`）、已安装包、网络可达性。
`Get-Command` 返回空 ≠ 机器没有这个能力。

### 未完成：MP4 编码
`archive\scripts\winui-png-to-mp4.ps1` 已写好（P/Invoke 调 MF，手写 4 个 COM 接口），
但**当前失败**：
```
System.AccessViolationException: Attempted to read or write protected memory.
   at MfMp4.IMFMediaType.SetUINT64(Guid k, UInt64 v)
```
退出码 3221225477。

**症状分析（重要）**：崩溃点之前的 `SetGUID(MF_MT_MAJOR_TYPE, ...)` / `SetGUID(MF_MT_SUBTYPE, ...)`
**没有报错**。手写 vtable 时这是典型的**槽位错位**信号 —— 调用落到了别的槽上
（例如 `SetGUID` 落到真的 `GetGUID`，`SetUINT64` 落到某个 `out` 方法，于是写坏内存）。
⇒ **修法应是核对 vtable 槽位/接口声明，不是靠 try/catch 掩盖。**

已核对：`IMFAttributes` 33 个方法，`IMFMediaType` 在其后加 5 个，共 38 个。
`MF_MT_*` 系列 GUID 已逐个与 SDK 头文件核对过（含 `MF_MT_INTERLACE_MODE` = `e2724bb8-e676-4806-b4b2-a8d6efb44cc0`，
此前脚本里误写成 `...b44cc`，少一个字符 → 已修正）。

**已委派子代理攻坚**（agent `1b1a07e1-…`），要求：不许装软件、不许改系统设置、
success 判据含"必须独立证明是可解码视频（解回帧做像素对比或读 MP4 box 结构）"，
