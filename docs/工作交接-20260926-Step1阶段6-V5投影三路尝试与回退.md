## 2. V5 三条路径的实测结论（**本轮核心产出，下一位必读**）

### 路径 1：Composition `SpriteVisual` + `DropShadow`（挂到卡片）→ ❌ 无效

- 做法：`ElementCompositionPreview.SetElementChildVisual(card, sprite)`，`sprite.Shadow = compositor.CreateDropShadow()`。
- 结果：**截图逐行亮度剖面与改前完全一致**（y 665–690 全部同一组数字），即画面上**没有任何变化**。
- 原因判断：`SpriteVisual` 默认尺寸 **0×0**，没有内容就没有可投影的轮廓。

### 路径 2：`ElementCompositionPreview.GetElementVisual(element).Shadow = dropShadow` → ❌ **编译不过**

- 结果：`error CS1061: "Visual" 未包含 "Shadow" 的定义`（WinUI 3 / WindowsAppSDK 2.3.9 的 `Visual` 上没有可用 `Shadow` 属性）。
- 已回退。

### 路径 3：在 MainWindow.xaml 把两张卡片包进 `<Grid>` 并在其后叠一条渐变"投影带" → ⚠️ **视觉有效，但打破布局，已回退**

- **视觉有效性（有实测）**：改动后主区 y 665–690 的亮度谷从 **−3 点** 加深到 **−6 点**（236 → 228 → 242 回升），云端视觉复核确认："两张卡片下边缘外侧均可见一层浓度很低、向外扩散的暗色阴影，过渡自然，无硬边/色阶/脏斑，未侵入卡面、不影响可读性"，并把**投影评分从 5/10 提到 7/10**。
- **为什么必须回退（有实测）**：包一层 `<Grid>` 之后**整个布局漂移**：
  - OCR 行数 **41 → 39**；
  - 「连接旧电脑」标题行从 y≈205 **跑到 y≈375**；可用共享卡从 y≈566 **跑到 y≈994**；
  - 云端视觉独立描述："主区标题行被上层半透明面板压住只露上半截"、"可用共享面板与连接表单面板**上下顺序颠倒**"、"主区中下部约三分之一高度几乎全空，只有两条被遮罩的横向残影"。
  - 根因：`Grid.Row="1"` 的包裹层在 `RowDefinition Height="*"` 的行里**没有把星号高度传下去**，卡片自身高度塌缩/溢出，导致主区各行错位重排。
- **已完整回退**：`MainWindow.xaml` 与 `MainWindow.xaml.cs` 从 `stage5\package\source\…` 还原，SHA256 与阶段 5 判断包**逐字节一致**。

### 下一轮若继续 V5，建议路线（按可行性排序）

1. **不要再用"包一层 Grid"的写法**；若走 XAML 路线，应把投影带放进**卡片内部**（`<Border>` 里包一层 Grid + 底部投影带），或改用 `Canvas`/`Translation` 精确对齐，且**改完必须立刻跑 OCR 行数比对（41 行）作为布局回归的硬信号**。
2. 走 **Composition 路线时必须给 `SpriteVisual` 显式设置 `Size`**（`sprite.Size = new Vector2((float)card.ActualWidth, (float)card.ActualHeight)`），否则 0×0 无投影；同时把 shadow 的 `Offset` 设为正值向下。
3. 或接受"投影由描边+底色承担"，把 V5 判为**不可达**并如实记入 V12 验收结论。
