   你的 baseUrl 与密钥从头到尾都是对的。真因是

       5867 个 reasoning token，实测单次耗时 **133.5 秒**；换成 qwen3.8-flash 后
       仍为 **33.1 秒**；而插件 timeoutMs 默认只有 **30000** → 每次都被自己的超时砍掉。
     实测证据（直连你的端点，与插件同参数）：
       纯文本请求          1,951 ms   成功
       450 字节纯色小图   17,574 ms   成功（reasoning 772 tokens）
       15KB 裁剪截图      17,729 ms   成功（reasoning 548 tokens）
       437KB 完整截图    133,464 ms   成功（reasoning 5867 tokens）
     插件日志另有 48 条记录、**零成功**，全为 timeout（upstream≈29.6s）。
   你把 timeoutMs 改到 120000 后立刻恢复可用。

一、本轮 7 项标注修复（全部有实测证据）

【A】输入框占位文字仍偏上 —— 已修复（真因与本轮前三轮都不同）
  用户原话：「输入框内的文字偏上没有垂直居中的问题还是没有得到解决，
             你得使用我的划线法来验证，直到彻底解决」
  用户划线法的含义（从标注图读出）：在文字上方画一条横线、左侧画一条竖线，
  竖线从文字底边一路量到输入框底边 —— 指出「文字下方留白明显大于上方」。

  ★ 真因（本轮才查清，前几轮的方向都是错的）：
    我在 Themes\TextInputTemplates.xaml 里定义的**隐式样式（无 x:Key）根本不会被应用**
    到实际的 TextBox。用两个"不可误判"的探针证实：
      ① 隐式样式里把 Background 设为 #FF00FFFF → 输入框**没有**变青色；
      ② 模板里加 8 DIP 纯红 Border → 页面上**找不到**红条。
    而把同一样式改成**显式 x:Key 并写到元素上**后，红条立即出现、文字位置随之改变。
    → 所以前几轮改 Padding / Margin 全部无效，因为它们都没进入渲染路径。

  ★ 修法：
    · 样式改为显式 key：`PCMigTextBoxCentered` / `PCMigPasswordBoxCentered`，
      显式写到全部 8 个输入框上（Step1 五个、Step2 两个、Step4 一个）。
    · 模板保留框架完整 PART_ 与 VisualState（ContentElement / PlaceholderTextContentPresenter /
      BorderElement / HeaderContentPresenter / DeleteButton / RevealButton / DescriptionPresenter），
      只给 ContentElement 与占位 Presenter 增加垂直对齐绑定。
    · 光学补偿用 Margin 并**按实测标定**（框恒为 y=270..316、中心 293）：
        Margin.Top=30 → 偏移 +9.5 DIP
        Margin.Top=14 → 偏移 +1.5 DIP
        → 斜率 0.5 DIP/DIP，解得 Margin.Top=11 → **实测偏移 +0.5 DIP**（目标 0）
      最终值 Margin="1,11,1,0"。
  ★ 验收：视觉复核确认「上下留白大致相等、垂直居中」；像素实测 +0.5 DIP。
  ⚠ 注意：该模板目前只显式应用到上述 8 个输入框；若以后新增输入框，**必须**显式指定这两个样式，
     否则会退回框架默认模板（隐式样式在本项目不生效）。

【D】浮层弹出位置错误 —— 已修复
  用户原话：「可读性不高，而且弹出来的位置错误，我希望它的**打开点击的按钮在哪，

  修法：PositionOverlayPanels() 改为**左缘对齐触发按钮**（每个浮层用自己的触发按钮：

【E】侧栏四个步骤卡缺"一致性光源浮雕" —— 已修复（本轮第三轮）
  用户原话：「这四个大板块按钮step1,2,3,4。没有做出和全局一样的浮雕效果，
             就是高光和阴影 Liquid Glass-inspired Edge Lighting 效果里的一致性光源」
  ★ 真因（物理原因，不是没画）：侧栏卡片自身底色实测 RGB(251,253,255)、亮度 252.9
    （近纯白），而原"顶边亮线"用的是**白色**渐变画刷 —— 白叠白，无论多亮都不可见。
    即"已加高光却看不出浮雕"是因为**没有对比度可用**。
  ★ 修法：浮雕 = 亮边 + 暗边 的成对对比。新增两个高对比边缘画刷
    （Colors.xaml：NavCardEmbossTopBrush 近实心白、NavCardEmbossEdgeBrush 半透明深蓝），
    外层 Border 承担浮雕（上缘亮线 + 左上到右下渐隐 + ElevationMedium 阴影 + Translation Z 8），
    内层 Border 继续承担选中态蓝边；方向与全局一致（光源左上 → 上缘亮、下缘暗）。
  ★ 验收（像素测量，非模型判断）：卡片上缘亮度跃变
        第1张 10.4 → **67.2**
        第2张 11.6 → **67.7**
        第3张 10.0 → **67.1**
     即提升 **6.4 倍**；同时卡底边实测存在暗边（亮度 237 → 131），下沿收边成立。
  ⚠ 诚实说明：视觉模型对同一张图给出过互相矛盾的判断（一次"弱-中"、一次"没有"），
     故本项**以像素测量为准**。若你仍感观不够，可继续加大边缘画刷对比度。

【F】标题栏版本号不该套蓝色胶囊 —— 已修复

    右侧确实有带时钟图标的『更新日志』文字按钮」。

【G】版本号悬停变白看不清 —— 已修复
  用户原话：「为什么我的鼠标放上去，这个版本号显示变成白色了？？」
  根因：头部 v0.5.0 徽章是**显式设置 Background 的普通 Button**，用的是 WinUI 默认 Button 模板，
        PointerOver / Pressed 会叠加默认浅色悬停层并可能改写前景，把白字洗成看不清。
  修法：新增 `PCMigVersionBadgeButton` 样式 —— **四态全部显式锁定**：
        背景只由传入渐变决定、文字恒为白色，悬停仅做极轻的透明度变化（0.88 / 0.74 / 0.45），
        绝不替换颜色。徽章保留（它是更新日志入口），只是不再有"看不清的悬停态"。
  ★ 验收：模板四态已锁定；本轮未做悬停态截图（需真实鼠标悬停），
    此项以"消除默认模板的浅色悬停层"为机制保证，**建议你实际悬停一次确认**。
