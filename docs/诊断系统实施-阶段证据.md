### 第二轮：主控回读 + 反例

回读中实际发现并修掉两个**会静默丢数据/静默失效**的缺陷（都由测试抓住）：

1. `DiaSerializationFailedPayload` 的位置参数命名为 `PayloadName`，与 `IDiagnosticPayload.PayloadName` 同名
   ⇒ record 编译器**不生成**该位置参数的属性（CS8907），传进来的值被静默丢弃。
   修为 `FailedPayloadName`，并新增两条返工护栏测试（`PayloadNameAlwaysMatchesTheStaticNameConstant`、
   `EveryConstructorParameterActuallyReachesTheRecord`）。
2. `EventCatalog` 静态字段初始化顺序：`Retired` 声明在 `Descriptors` 之后 ⇒ `BuildAll()` 读到 null
   ⇒ `TypeInitializationException`（`Intersect(second: null)`）。已把 `Retired` 前移并写明"声明顺序有语义"。

编码/回读对称性核对：writer 侧 55 个字段名 vs parser 侧 47 个 `case`，差额 8 个全部是嵌套 `path`
对象的内部字段（经 `PayloadJson` + `ReadPath` 读取），并由 `EnvelopeWithEveryOptionalFieldRoundtripsExactly`
用 record 结构相等**逐字段**断言（含 8 个 path 字段）。不存在"只写不读"的字段。

## D2 · Diagnostics Runtime（完成）

### 范围与产物

新增项目 `src\PCMig.Diagnostics\`（net8.0，只引用 Abstractions 与 BCL；**零第三方依赖**）。
装配出的管线与方案 §5 的图**逐项对应**：

```text
生产线程 → DiagnosticHub.TryPublish（过滤 → 盖戳 → 截断/掩码 → 一次非阻塞 TryAccept）
   → ingress-critical / ingress-operational / ingress-verbose   ← 按 DeliveryClass 分队列
       → FanOutStage（后台显式广播，**不是**多读者抢同一 Channel）
            ├→ writer 收件箱   → JsonlSegmentWriter（单写者 / 分段 / 封段清单 / Flush(true) ack）
            ├→ analyzer 收件箱 →（D4 接规则引擎；当前只测滞后）
            └→ viewer 收件箱   → ViewerEventCache（有界显示缓存）
   → FlightRecorder（独立字节预算的内存环 + 触发前后窗口 + 低频有界检查点）

DiagnosticRuntime 另提供：自身 health 快照、LossLedger、RedactionPolicy、Meters、
分支统计、有界关闭（ShutdownAsync）、fail-open 启动（存储不可用 ⇒ 只跑内存分支）
```

| 文件 | 职责 |
|---|---|
| `DiagnosticHub.cs` | IDiagnosticPublisher 实现；唯一 fan-out 点；`CreateDetached` 供关闭路径写"最终状态事件" |
| `BoundedBranch.cs` | 有界分支：条数闸门 + **字节闸门** + 逐条 loss 记账 + 非阻塞 TryAccept + 有界关闭 |
| `ByteBudget.cs` | 字节预算（Channel 原生只限条数，事件大小差异极大） |
| `FanOutStage.cs` | 显式广播：writer 卡住不影响 analyzer/viewer；Verbose 不进分析/显示 |
| `LossLedger.cs` | 丢失台账：per-branch/class 聚合 + **Epoch** + DurableCritical sticky |
| `DiagnosticHealth.cs` | 自身健康计数（Interlocked/Volatile，**不经过 logger**，无递归） |
| `JsonlSegmentWriter.cs` | 单写者、复用 buffer 的序列化（无每事件 MemoryStream+string）、滚动、封段清单、存储故障有界退避 |
| `SegmentRecovery.cs` | 末行截断恢复 + CorruptLines 计数 + SHA256 清单 |
| `RetentionManager.cs` | 配额/年龄清理，只删已封段、拒绝 reparse 穿越、尊重 pin |
| `FlightRecorder.cs` | 有界内存环 + 触发合并/冷却/并发上限 + 前后窗口封存 + 有界检查点 |
| `ViewerEventCache.cs` | 有界显示缓存（覆盖计数可见，绝不反压 writer/analyzer） |
| `RedactionPolicy.cs` | 入口侧脱敏：HMAC 令牌、PathRef、文本掩码（无正则、确定性） |
| `DiagnosticMeters.cs` | Meter + 低基数 tag（禁止 JobId/ObjectId/Path 成为指标维度） |
| `DiagnosticSessionStore.cs` | 目录布局、session.json、catalog.json、clean marker、上次会话未确认检测 |
| `DiagnosticRuntime.cs` | 装配根、1 秒维护节拍、有界关闭、fail-open |

### 第二轮：主控回读 + 反例

回读与测试抓到并修掉四个真实缺陷（都不是"测试写法问题"，而是实现缺陷）：

1. **Flight 窗口因文件名非法而永远落不了盘**：`TriggerId` 直接拼了规则码（`rule:UI_FEEDBACK_MISSING`），
   冒号在 Windows 文件名中非法 ⇒ 持久化必然失败且只表现为"PersistedWindows=0"。
   现在文件片段做白名单化（原始 triggerCode 仍原样保留在 `DIA.RingTriggered` 载荷里）。
2. **`ControlId` 被静默丢弃**：DiagnosticContext 里有 ControlId，但 DiagnosticEvent 没有该字段、
   hub 也没写 ⇒ D4 的 UI 规则将拿不到控件身份。已补进 envelope + JSON 读写 + hub 赋值 + 断言。
3. **占位符与 JSON 转义冲突**：占位符原为 `<path>`/`<redacted>` 等，而 `Utf8JsonWriter` 默认编码器会把
   `<`/`>` 转义成 `\u003C` ⇒ 导出包里的脱敏标记变成不可读乱码。已统一改为 `[path]`/`[redacted]`/
   `[unavailable]` 风格：既保持 JSON 安全默认（不换 UnsafeRelaxedJsonEscaping），又保持可读。
4. **过载静默风险**：突发探针一开始"以为"应该零丢失，实测 2 万条瞬时灌入必然产生丢失。
   已把口径改成两条独立契约——**真实量级零丢失** + **过载必须可见（台账/Epoch/EvidenceComplete）**，
   而不是把测试放宽来掩盖。

另：`xUnit1031`（38 处 sync-over-async）没有用抑制器糊过去，而是：
库内 await 一律 `ConfigureAwait(false)`（已核对，含 BoundedBranch/DiagnosticRuntime/泵），
测试侧集中到 `D2TestSupport.Shutdown/Dispose/Stop/Route/Write` 五个助手（一处审查替代 38 处散落）。

## D4（部分完成）· 确定性规则引擎 + 首批 5 条规则

### 范围与产物

**`Analysis/Incident.cs`**：事件卡模型。字段刻意分清
`Facts`（每条都是指向**某一次**事件的 `EventRef`）/ `Candidates`（候选原因，带支持与**反证**）/
`Missing`（缺什么证据 + 当时覆盖水位 + 采集是否健康）/ `BreakPoint` / `Confidence` +
`ConfidenceRationale` / `SuggestedChecks` / `Status` / `Revision`。
置信度是**证据强度带**（ConfirmedObservation/High/Medium/Low/Unknown），**没有伪概率**。

**`Analysis/RuleEngine.cs`**：
- 作为 **analyzer 收件箱的消费者**接入（`writer` 与它互不拖累）；
- 分派按**稳定事件名**（`ForEventDescriptor`）；注册表重复 ID 直接抛错；
- **证据不足就降级**：`RequiresCompleteEvidence=true` 的规则在 `lossEpoch>0` 或存储降级时，
  结论落成 `Inconclusive` 并填 `MissingEvidence`（"无法区分没发生与没记到"）；
- **代际隔离**：事件卡身份统一附 `|g{runGeneration}` ⇒ Run A 的迟到事件只修订 A 的卡；
- **冷却抑制 + 活动卡上限（256）+ 单卡证据条数上限**：风暴不会无限增长，且抑制量可见；
- **规则异常隔离**：单条规则抛异常只计入 `RuleFaults`，不影响其它规则；
- 迟到/重复 = 同一张卡的**修订**（Revision++），不是再来一张互相矛盾的卡；
- 事件卡生命周期回调 ⇒ runtime 发 `DIA.IncidentOpened/Resolved`，并在**错误级**开卡时触发飞行窗口。

**首批 5 条规则**（`Analysis/Rules/EvidenceRules.cs`，全部为"硬证据"型，不依赖缺事件推断）：

| 规则 | 判据（稳定 token + typed payload） | 结论强度 |
|---|---|---|
| `PERSISTENCE_WRITE_FAILED` | `PST.WriteFailed` / `PST.WriteSkipped` + `PstWritePayload`；Receipt/Plan ⇒ **Error**、JobState 视图 ⇒ Warning | ConfirmedObservation |
| `DIAGNOSTICS_DEGRADED` | `DIA.EventsDropped/CriticalLost/StorageFailed/AnalyzerLagged/Backpressure` | ConfirmedObservation（自身计数） |
| `ACCESS_DENIED` | 错误域 **Win32** 且码为 5/65/1326（或 UnauthorizedAccess/Security） | High |
| `TARGET_SPACE_EXHAUSTED` | Win32 112/39（**不**把 robocopy 退出码 8 单独当空间问题） | High |
| `ROBOCOPY_UNEXPECTED_EXIT` | `RBC.ProcessExited` 且 `exitCode>=8` 且**非**被我们取消（-1/Canceled 排除） | High |

## D5 剩余子项 · Deep Trace 有限 Routed 输入观测（完成）

### 三、被修正的口径与参数（不改语义，只纠正"说错了"）

- `UI.ProjectionReadback` 投递类 **Verbose → Operational**（否则正常模式根本采不到 L2）。
- `AnalyzerMaxPending` **1024 → 4096**：实测 2000 条突发下 analyzer 收件箱是最窄一环，会丢事件并让反馈类规则降级。
- `DiaSessionStartedPayload.StorageRoot` → **`StorageRootToken`**（原始路径含用户名，属 Personal）。
- 导出：**所有 JSON 结构化生成**（`Utf8JsonWriter`），事件行与卡片行按结构深度清洗；`session.json` 用每包别名。
- 解析器：按**字段存在性**校验必填；未知/缺失 `eventVersion` ⇒ `UnsupportedVersion`（**不再静默归一**）；未知 EventId 不解码 typed payload；规则遇 unsupported 整条跳过。
- 新增/删除的配置项：新增 `MaxEventBytes`、`FlightMaxFinishedWindows`、`FlightWindowPayloadByteBudget`；**删除** `FailOpenToNoOp`。
- 「统计完整性」成为一等证据：Verifier 新增枚举跳过计数（**只计数，不改跳过决策**）+ `VRF.StatsCompletenessObserved`。
- UI 生命周期：面板**五条关闭路径**统一收口；导出移到后台线程并支持取消（不新增控件）。
