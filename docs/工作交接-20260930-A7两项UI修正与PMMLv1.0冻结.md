### 阶段 A7：两项明确 UI Bug + 一项衍生位置问题

**B1 — Step1「连接时测速」说明文字与 Toggle 不垂直对齐（已修）**
- 根因：水平 `StackPanel` 子项默认 `Stretch`，`TextBlock` 从框顶绘制文字 ⇒ 视觉偏上约 8px。
- 修法：只给该 `TextBlock` 加 `VerticalAlignment="Center"`（**唯一改动**，容器 Margin/Grid.Row/其它控件未动）。
- 文件：`src\PCMig.WinUI\Views\Step1ConnectPage.xaml`
- 验收：4× 放大截图确认对齐。

**B2 — 线程数 ComboBox 下拉浮层前景发糊（已修）**
- 根因：`UniformScaleHost.DesignHeight = 892` 与 `MainWindow.CanonicalClientHeightDip = 891` 差 1px ⇒ 默认窗口下 Viewbox 按 `891/892 = 0.99888` 做**分数缩放**；而 ComboBox 的 Popup 是**独立视觉岛**，被重采样 ⇒ 发糊。
- 修法：`DesignHeight` 892 → **891**（一行常量）。
- 文件：`src\PCMig.WinUI\Presentation\UniformScaleHost.cs`
- 实测（原生分辨率、与对比度无关的边缘分布）：强边缘 409 → **776**、边缘均值 75.7 → **95.8**；参照（完全关掉 Viewbox）927 / 98.5 ⇒ 修后接近参照。
- **残留未解释**：仍略低于参照值（同色对照那次没抓到浮层）——如实登记，见第四节。

**B3 — 下拉打开动效改为「自上而下卷帘」（已完成，用户已认可）**
- 做法：逐字复制官方 `DefaultComboBoxStyle` 生成项目自有模板（`PcmigComboBoxRollStyle`），三处机械改动：
  1. key 改名；2. 模板内 9 处 `{StaticResource}` → `{ThemeResource}`；3. `DropDownStates` 用 `RollScale.ScaleY 0→1`（Opened `0.20s` EaseOut / Closed `0.13s` EaseIn）替换官方 `SplitOpen/CloseThemeAnimation`，并清空 `Popup.ChildTransitions`。
- 唯一无法保留：框架内部附加属性 `primitives:ComboBoxHelper.KeepInteriorCornersSquare`（应用侧不可引用）⇒ 已作为单条 delta 记录。
- 保真度实测：新样式 vs 官方默认样式打开态 **像素总差 0.2%**（差异仅在左右边缘）⇒ 材质/圆角/阴影/选中 pill/尺寸与官方一致。
- 文件：`src\PCMig.WinUI\Themes\PcmigComboBoxRoll.xaml`（生成物）、`App.xaml`（注册）、**生成脚本** `archive\scripts\a7-make-combobox-rollstyle.ps1`（唯一来源，升级 WinUI 后重跑）

**B4 — 删除「新建任务」假条目（已修）**
- 下拉只列真实任务；无任务即空白；选中态**按 JobId 保留**（不再按位置）。

**衍生问题：原生 ComboBox 浮层位置（已通过改架构绕过，不再对抗）**

### 阶段 A7.1：「已有任务」Task Picker 收口（用户裁决方案，已完成）

**① 真实业务 Bug（最高优先级）：旧索引 ±1 残留（已彻底清除）**
- 根因：第 1 项曾硬编码为伪条目「新建任务」，故有 `SelectedIndex = idx + 1`（QA 探针）与 `jobs[idx - 1]`（选择处理器）补偿；伪条目删除后补偿未撤 ⇒ 点 JOB-A 被当成"新建任务"、点 JOB-B 实际载入 JOB-A。
- 审计结果：`ExistingJobsCombo` / `idx - 1` / `idx + 1` / `SyncExistingJobsCombo` / `AlignJobsDropDownBelowCombo` **全部为 0 命中**（仅清理与该旧占位模型相关的残留，其它模块的 `SelectedIndex` 未动）。

**② 新结构（Task Picker）**
```
Button（收起态 Presenter：同款 ComboBox 背景/边框/圆角/箭头，Height=ComboBoxMinHeight≈32，单行 ellipsis）
 └─ Flyout Placement="BottomEdgeAlignedLeft"   ← TAOP，框架正常锚定（无魔法偏移/负 Margin/TranslateY/运行后校正）
     └─ ListView（SelectionMode=None + IsItemClickEnabled，ItemsSource = session.ExistingJobs，MaxHeight=320 自带滚动）
```
- **点击语义对象化**：`ItemClickEventArgs.ClickedItem as JobSummary` → `job.JobDir` → `AdoptExistingJobAsync` —— **零索引运算**。
- **显示 ≠ 已载入**：收起态由 `UpdateExistingJobsPicker` 计算（有 CurrentJob 显示它；否则第一条真实任务作 **preview**；都没有显示「（暂无任务）」），**不写任何 SelectedIndex** ⇒ 点第一条必然触发。
- 视觉继承：背景/边框/圆角/选中 pill/悬停色取自框架同套 ComboBox 主题资源。
- 已删除：`AlignJobsDropDownBelowCombo()` + `DropDownOpened` 订阅（实测无效补丁，不留生产代码）；QA 探针改为**按 JobId 找对象**，不再用 index。
- 实测验收（真机合成点击 + 取证日志）：
  ```
  click JobId=JOB-20260930-122535-a095 (listIndex=0) → current=…a095  match=True   ← 第一条可正常载入
  click JobId=JOB-20260930-122035-3312 (listIndex=3) → current=…3312  match=True
  click JobId=JOB-20260930-121847-49fc (listIndex=4) → current=…49fc  match=True
  ```
  每次点击之间都发生一次 `RefreshExistingJobs`，仍逐次 `match=True`。
- 浮层位置实测（真实点击路径）：控件底边 **y=383** → 浮层顶边 **y=389**（间距 6px，向下展开）；收起态 Presenter 实测 **34px**，与旁边「线程数」同 band。
