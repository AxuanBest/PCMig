## 二、KILL 场景：通过的是"后果断言"，未通过的是"打断时机"

因为现代化 NVMe + 小数据集（4001 文件 / 7.88 MB）在 **2 秒内完成迁移**，20%–60% 的进度窗口只有约 0.5 秒，轮询（250ms）难以命中。

| 断言 | KILL-01 | KILL-02 | 说明 |
|---|---|---|---|
| 打断时机 | **NOT_RUN** | **NOT_RUN** | 未真正命中窗口 → 不判 PASS（防假 PASS 纪律） |
| 无孤儿 robocopy | **PASS** | **PASS** | 基线 0 → 现状 0 → **新增 0**（用"基线+新增"判定，避免误算别的进程） |

| Verify-JobState | **PASS** | **PASS** | phase=completed / failedObjects=0 / percent=100 |
| Verify-Integrity | **PASS** | **PASS** | **4001 文件全量 SHA256 一致 + 目录结构一致** |

### 要真正命中打断窗口，需要（下一轮改进项）

1. **放大数据集**到 30,000+ 小文件或 ≥512MB 大文件（迁移 30 秒以上）；
2. 或**降低轮询间隔**到 50ms；
3. 或改用**对象级进度**（读 `job-state.json` 的 `completedBytes`）而非目录字节数。

> 当前实现已把这三条写进脚本注释，下一轮直接调参即可。

## 四、STATE-01：状态损坏恢复（全部 RUNTIME_VERIFIED）

**手工把 `job-state.json` 写成非法 JSON 后，PCMig 的真实输出（逐字）**：

```
⚠ 状态文件 job-state.json 损坏无法解析：进度未知（待由回执重建），下面不显示 0.0% 这类会误导脚本的数字；回执与验证结果不受影响。
Job JOB-20260919-143904-b45b  阶段: 未知（状态文件损坏/缺失，待由回执重建）  进度: 状态损坏，待由回执重建（本行故意不显示 0.0%）  对象: 未知（以回执为准，run/resume 会按回执重建）  更新于 14:39:07
```

**这是教科书级的正确行为** —— 明说不显示误导性数字、明说以回执为准、且 exit=0 不崩。

### 一处重要的断言教训（已修）

首版断言用 `输出 -match '0\.0%'` 直接判 FAIL，**结果把 PCMig 解释文字里的 "0.0%" 也算成违规** → **误判**。

修正为**语义化判定**：允许在解释文字中出现，**只禁止"进度行"给出 0.0% 数字**：

```powershell
foreach ($ln in ($st.Output -split "`r?`n")) {
  if ($ln -match '进度\s*:' -and $ln -match '0\.0%' -and $ln -notmatch '不显示|故意') { $progressLineShowsZero = $true }
}
```

> 教训入册：**断言要匹配"行为语义"，不能匹配"字符串出现过"** —— 否则会把产品的正确提示判成缺陷。

## 五、本轮修掉的脚手架缺陷（B3 期间暴露，共 4 处）

| # | 缺陷 | 现象 | 修复 |
|---|---|---|---|
| S11 | **函数内 `Write-LabLog` 污染管道** | `Compare-LabTree -ProgressEvery` 返回 `[进度字符串..., 对象]` 混合数组 → 调用方 `$cmp.Status` 报 `PropertyNotFound`，**完整性核对结果丢失** | 函数内改用 `Write-Host` |
| S12 | **`@(fn)` 与 `,@()` 的双重包裹** | `return ,@(...)` 后调用方再 `@()` 包裹 → `foreach` 迭代的是"数组"而非元素 → `$r.Id` 报 `PropertyNotFound`，Cleanup 失败 | 统一为 `return @(...)`（扁平），调用点用 `@()` 兜底 |
| S13 | **robocopy 孤儿判定误报** | 直接用"现状数 = 0"判定，把**别的进程遗留的 robocopy** 算成本次孤儿 | 改为"**基线 + 新增**"判定 |
| S14 | **字符串匹配改脚本导致文件损坏** | 用 `-replace` 批量改 `.ps1`（含转义）→ **文件被截断为 1 行**、语法全废 | 放弃字符串补丁，**整体重写文件**；印证项目纪律"禁止注释式批量替换" |

> S14 是真实事故：我用行级/字符串替换改脚本，一次把 511 行的 `fault-lab.ps1` 写成 1 行。**这正是 v0.3.7 事故的同类**，现已按纪律改为整文件重写。
