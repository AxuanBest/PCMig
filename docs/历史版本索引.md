# PCMig 历史版本索引

> 本文件是 PCMig 历史版本的**证据索引**，不是用户手册，也不是更新日志。
>
> **记录口径**：只写能从仓库或归档中**实证核对**的事实。没有证据的格一律填 `—`，不做推测、不靠版本号推断、不因为「界面老」就认定某版本支持某系统。
>
> **最后更新**：2026-10-06（当前正式版本 = v0.5.1）

---

## 〇、这份文档回答什么

1. PCMig 一共发布过哪些版本、各自什么时候发的、属于哪个 UI 世代。
2. 每个版本的三类硬证据是否存在：**正式安装包 / 更新日志条目 / 公司环境测试报告**。
3. 哪些版本**留有精确源码快照**（可逐文件核对到声明版本号），哪些只剩安装包。
4. 历史 tag 的**实际**状态（tag 名 ≠ 版本快照，详见第八节）。
5. Windows 兼容性的**证据等级**（VERIFIED / LIKELY / UNVERIFIED / UNSUPPORTED）。

本文件**不做**「哪个历史版本最好」的主观排序，也**不创建任何 tag**（建议只写在第七节）。

### 历代安装包总清单（发布用）

上述 51 个安装包的完整指纹清单已单独整理为 **`LEGACY-INSTALLERS-SHA256.txt`**，共 **11 字段 × 51 行**：

| 字段 | 含义 |
|------|------|
| `Version` / `FileName` / `SizeBytes` | 版本号 / 安装包文件名 / 字节数 |
| `SHA256` | 该安装包的唯一内容指纹（去重依据） |
| `FileVersion` / `ProductVersion` | 安装包内 `VersionInfo` 原值（如实记录，含历史遗留） |
| `ReleaseDate` | 由更新日志版本对照表得出 |
| `ExactSourceSnapshot` | `EXACT_SNAPSHOT_A`(5) / `RANGE_SNAPSHOT_B`(3) / `UNAVAILABLE_IN_CURRENT_GIT`(43) |
| `Evidence` / `Notes` | 证据出处 / 历史备注（如 v0.2.0–v0.2.3 的 `FileVersion` 仍写 `0.1.0.0`） |

**该清单的发布方式**：安装包属**发布产物**，不作为源码提交进 Git 仓库（避免永久膨胀仓库历史，且单包已超过普通 Git 的 100 MiB 上限）。因此该清单与历代安装包二进制**一并作为 GitHub `PCMig Legacy Installers Archive` Release 的 asset 发布**。

> `legacy-installers-archive-<日期>` 这个归档 tag 只表示「把历史安装包集中发布到 GitHub 的归档节点」，**不表示**任何历史版本的源码 commit，也**不是**版本 tag。

## 三、Legacy —— **有**精确源码快照

判定标准（三者满足其一）：
- **A 级**：git commit 内 `src/PCMig.Gui/PCMig.Gui.csproj`（或 WinUI 同名文件）的 `<Version>` 与版本号一致；
- **B 级**：归档源码镜像/源码包的 csproj `<Version>` 与版本号一致（可逐文件 SHA256 核对）；
- **C 级**：仅安装包内的二进制（可读 `VersionInfo`，但**不能**还原源码）。

本组全部为 **A 级或 B 级**。共 **8 个版本**（含前代正式版本 v0.5.0）。

## 六、Windows 兼容性证据等级

等级定义：`VERIFIED` = 有实际运行记录；`LIKELY` = 由目标框架与依赖推导、但无该组合的运行记录；`UNVERIFIED` = 无任何记录；`UNSUPPORTED` = 有明确的反证或框架矩阵不支持。

| 平台 | WPF 世代（v0.1.0–v0.4.9） | WinUI 世代（v0.5.0+） | 证据 |
|------|--------------------------|------------------------|------|
| Windows 11（build 26200） | **VERIFIED** | **VERIFIED** | 公司域机 `SZLT502920`（非管理员）+ 本机同 build 的实机测试记录 |
| Windows 10 build 19041+ | **VERIFIED** | **LIKELY** | 更新日志 v0.1.0 小节记录「改用真实 VMware Windows 10 虚拟机完成端到端实测」**但未记录 build**；WinUI 要求 `net8.0-windows10.0.19041.0` |
| Windows 10 1607–1803 | **LIKELY** | **UNSUPPORTED** | WPF 仅要求 `net8.0-windows`；WinUI 目标平台最低 19041 |
| Windows 8.1 / 7 | **UNSUPPORTED（作运行平台）** | **UNSUPPORTED** | .NET 8 支持矩阵不含；仓库内**没有任何**以 Win7/8.1 为运行平台的测试记录 |
| Windows Server | **UNVERIFIED** | **UNVERIFIED** | 无任何记录 |

**Win7 的正确口径**：`docs/使用说明.txt:397` 与 `:472` 提到 Win7 —— 那是**旧电脑作为 SMB 数据源**时「本地管理员账号需用内置 Administrator」的运维提示（UAC 远程令牌过滤），**不是**说 PCMig 能装在 Win7 上运行。**不要**把 v0.4.x 描述成「支持 Win7」。

**安装器 OS 门槛**：`installer/pcmig.iss` 在 `884f3dc` / `f46c170` / `9a77381` / `022377e` 四个快照中**都没有** `MinVersion` / `OnlyBelowVersion`，只有 `PrivilegesRequired=admin`、`ArchitecturesAllowed=x64compatible`、`ArchitecturesInstallIn64BitMode=x64compatible` ⇒ 实际的 OS 门槛完全由**随包自包含的 .NET 8 运行时**决定（自包含证据：本地历史交付包 `Portable/coreclr.dll` 存在）。

仓库的 git 历史是**后期整理而成**的：**65 笔提交装下了 51 个发布版本**，49 个版本 / 开发历史 tag 只落在 **18 个 commit** 上（另有 1 个归档 tag `legacy-installers-archive-20261006` 落在第 19 个 commit 上，与版本历史无关 —— 见第七节）。

|--------|------|--------|------|

**后果（必须写进任何引用历史版本的场合）**

## 九、未验证与已知缺口（如实记录）

1. **43 个版本无源码快照** —— 只能核到安装包级；不从二进制做源码还原。
2. **`installer/pcmig.iss` 的版本号在 v0.4.1 前后不同步** —— `f46c170` 的 csproj = 0.4.1 而 iss 仍写 0.2.5；版本号统一自 **v0.4.5** 开始。
3. **Windows 10 的确切 build 未记录** —— 更新日志只写「真实 VMware Windows 10 虚拟机」，故 Win10 条目对 WPF 世代定为 VERIFIED（有端到端实测）、对 WinUI 世代定为 LIKELY。
4. **Windows Server 完全无记录**（UNVERIFIED）。
5. **v0.4.2 系列的 4 个 tag 指向 WIP Material System 施工状态**，从未正式发布；本文件不把它们列为版本。
6. **两处命名与内容不符**（已在 3.2 / 3.3 标注）：`PCMig-v049-responsive-release-20260923` 实为 0.4.8；`PCMig-v0.5.0-这一版源码-20261005` 实为 0.4.9。
7. **本文件只做索引与证据标注**，不含「哪个历史版本更稳定」的排序 —— 没有实测数据支撑这种排序。
