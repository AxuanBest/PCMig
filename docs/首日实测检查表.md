# PCMig 首日真实环境实测检查表

> 目标：从 VMware 走向公司真实电脑。**不追求 100% 复制成功**，追求「失败也能说清楚哪个文件、为什么」。
> 建议第一次选一台不太重要、数据量较小的测试电脑，验证基本闭环：
> 旧电脑 → SMB → PCMig → 新电脑 → 文件打开 → 验证 → 报告。

## 0. 开工前（5 分钟）

- [ ] PCMig.exe 能正常启动（首次可能被 SmartScreen 提示，选「仍要运行」）
- [ ] 确认用的是**域管理员 / 旧电脑本地管理员**账号（不用用户自己的账号）
- [ ] 线程数保持默认 **16 或 32**（首次实测不要开 128）
- [ ] 让用户关闭 **Outlook / Excel / Word** 等办公程序
- [ ] 保留「连接时测速」勾选（默认开）——基准速度会写进报告

## 1. 连接与权限

- [ ] 旧电脑能连接（Preflight 全绿）
- [ ] 管理共享能访问（能看到 C$ / D$ 或对应共享）
- [ ] 链路测速结果合理（千兆网参考值：60~110 MB/s；明显低于 10 MB/s 先排查）
- [ ] Explorer 打不开 ≠ PCMig 连不上（反之亦然），以 PCMig 的 Preflight 为准

## 2. 真实数据覆盖（勾一台真实用户的机器自然就会碰到）

- [ ] 中文路径 / 中文文件名
- [ ] 含空格、括号、&、#、[] 的路径
- [ ] 长路径 / 深层目录
- [ ] 大文件（>512MB，会走 /Z 可续传通道）
- [ ] 大量小文件（走 /MT 多线程通道）
- [ ] 正在占用的文件 → 应出现在报错区并带处理建议，**而不是搞死整个任务**
- [ ] 隐藏文件 / 系统属性文件
- [ ] Office 瞬态锁文件（~$ 开头）应被自动排除，不产生噪音失败
- [ ] OneDrive 云占位符：报告/日志应有明确提示（需要时把矩阵 cloudPlaceholderPolicy 改为 Skip）

## 3. 安全软件观察（重点）

- [ ] PCMig 启动时无拦截/隔离告警
- [ ] robocopy 子进程能正常拉起
- [ ] 传输速度接近测速基准（掉到基准 30% 以下且持续 45 秒，界面会主动提示）
- [ ] 若被 EDR/DLP 拦截：记录告警内容，联系 IT 加白名单后重试

## 4. 完成与验收

- [ ] 迁移完成（或「完成(有错误)」但报告能说明每个失败的原因）
- [ ] 文件数 / 字节数与源基本一致
- [ ] **至少跑一次 L2 验证**（SHA-256 抽样）
- [ ] 打开 HTML 报告：核对「环境档案」区的速度/耗时/线程数
- [ ] 新电脑上随机打开几个真实文件（Office 文档、图片）
- [ ] 把报告归档：这是建立「公司环境正常速度」认知的第一份档案

## 5. 翻车了怎么办

| 现象 | 先查 |
|---|---|
| 连接失败 1326 | 账号密码；空密码账号被 Windows 策略禁止网络登录 |
| 能连但没有共享 | 该账号不是旧电脑管理员；管理共享被关 |
| 速度 < 基准 30% | 安全软件实时扫描 → 白名单 |
| 大量「文件被占用」 | 用户没关 Outlook/Office，关掉后点「恢复任务」 |
| 报「错误 112」 | 目标盘满了，清理后点「恢复任务」 |
| 报「错误 82」 | 目标盘是 FAT32，换 NTFS 盘 |
