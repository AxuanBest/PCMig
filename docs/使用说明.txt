■ v0.5.1 可信度紧急修正：目标盘写满不再虚报 99.9% + 旧 WPF 前端退出正式交付物
  · 修复（重要）：目标盘空间不足时，界面不再谎报"几乎全部完成"。
    以前遇到"源 42 GB、目标盘只剩 1.6 GB"这种情况，进度会在开始后约 1 秒就冲到 41.94 GB / 99.8%，
    随后钉在 99.9% 一动不动，底栏还同时写着"42 GB / 42 GB（99.9%），对象 0/41"——数字自相矛盾，
    而实际上 6 个大文件全部是"磁盘空间不足"、一个都没复制成功。
    本版修好后：这种失败会如实显示为"已完成 0 字节、任务结束但有错误"，并在日志里明确写出为什么终止。
  · 修复（重要）：为什么以前会谎报——两处缺陷叠加。一是传输引擎里"错误处理"和"转发给界面"共用同一条
    事件链，旧代码把界面转发排在了错误处理前面，界面上一次异常就把错误处理整段跳过（该扣回的字节没扣、
    该熔断的没熔断）；二是失败列表从引擎线程直接改界面集合，正好把异常抛在那条链上。两处都已修复。
  · 修复：两处原本会静默吞掉异常的地方（robocopy 输出泵）现在都会记日志。以前"什么都没发生"的故障，
    以后能在日志里直接看到原因。
  · 变化（重要）：从本版起，正式交付物里不再包含旧 WPF 前端。
    安装包与便携版只提供两个程序：PCMig.WinUI.exe（主界面）与 pcmig-cli.exe（命令行）。
    开始菜单里不再有"经典界面·回退"入口；安装完成自检只启动 WinUI 主界面。
    旧 WPF 源码仍保留在源码仓库里作为历史实现与回退参考，需要时自行编译，但不再随包发布。
  · 清理：删掉一个已经没有任何地方引用的旧动效驱动实现；修正一处过时的字段注释；测试产物目录不再混进提交。
  · 补齐验证：宿主替换后的进度画布卡顿量化、界面生命周期矩阵（反复进出页面 / 缩放 / 最小化还原是否累积画布）、
    非默认显示缩放下的进度控件宽度实测——三项此前只有源码推算、没有实测，本版补齐。
  · 验证：Core 569 / Diagnostics 382 个用例全部通过；目标盘写满场景连续 3 次通过、命令行对照连续 3 次通过。
    修复前实测为"已完成 45097156608 字节（正好 42 GiB）/ 99.9% / running / 熔断 0 条"；
    修复后为"已完成 0 字节 / completedWithErrors / 熔断日志 3 条"。
  · 如实说明：以上证据全部来自本机实验室与界面自动化夹具，尚未在真实物理机上复验。
    另有"先入账成功、随后失败"这一时间窗口在两次对照实验里都没有触发，该回退分支仍未被实测覆盖。

  · 功能范围：本版不是功能版，没有新增功能、没有界面调整、没有大规模重构；迁移引擎、任务存档格式与校验语义均未变。

■ v0.3.8 真实生产事故修复（78GB 漏传 + "看着像卡死"）
  · 事故：公司环境把旧电脑 7 个对象（148.31GB）迁到 D:\，界面显示 35.9%、对象 5/7、失败 2 个，
    速度只有 30 多 MB/s，用户以为卡死就停了；事后核对发现"完成"之后仍缺 5 个文件约 52.8GB
    （D:\ 根的 3 个散落文件 100% 没传 + 2 个 Outlook .pst 56.66GB）。
  · 根因一（盘符根路径被引号吃掉）：目标是盘符根 D:\ 时，命令行的引号把结尾反斜杠转义掉，
    robocopy 实际收到 "D:"，直接 Exit=16（严重错误、一个文件都没传），界面上只显示"失败"。
    现在源/目标/文件清单/排除项统一做引号规范化（结尾反斜杠加倍），盘符根与共享根都能正确传；
    实测根目录散落文件真的落到目标根（退出码 1~3），3 个普通对象回归全部一致。
  · 根因二（大文件通道太慢）：大文件一直用 /Z 单线程，实测只有手抄（/MT:32、137MB/s）的四分之一。
    现在大文件默认 /MT 多线程，SMB 链路额外加 /J（无缓冲）；本机 A/B 实测比 /Z 快 1.6~2.0 倍
    （6GB 单文件 /MT 1884~2906 MB/s vs /Z 1066~2088 MB/s；8×800MB 2275~2652 vs 1262~1338 MB/s），
    而 /J 在本地盘上会掉到 /Z 的一半，所以只在网络链路才加。
    /Z 保留为"可续传备选"：--large-channel auto（默认）/ restartable / multithreaded，
    auto 首次用 /MT，同一对象重试第 2 次起自动退回 /Z，日志会写明本次实际用了哪个通道。
  · 根因三（扫描残缺静默通过）：扫描遇到不可访问目录以前只打印一句"部分不可访问×N"就继续。
    现在会列出「哪条路径 + 什么原因」（如 访问被拒绝（权限不足）），并且默认拒绝开始迁移：
    pcmig new 退出码 3、pcmig run 退出码 5，阶段置 awaitingReview；修好权限后重扫，
    或加 --allow-incomplete-scan 显式承担风险（界面会弹窗逐条列出、默认选"否"，
    确认后写入任务文件，续传不再拦）。正常目录不受影响。
  · 界面不再"看着还在跑"：失败对象在左栏红色逐条列「对象号 + 路径 + 退出码译文」
    （如 16 = 严重错误：命令/路径无效，一个文件都没传；8 = 有文件复制失败）；
    暂停时写明「已暂停：已完成 X/Y 个对象，剩余 Z% 未传（可用「恢复任务」续传）」；
    传大文件时显示「当前对象：<路径>，已传 A/B」并提示
    "大文件复制期间可能数分钟无进度变化，属正常，请勿终止"，连续 45 秒没有字节进账才升级为
    「⏳ 进度停滞 N 秒」。命令行 status 也补上了退出码译文与"有失败对象＝迁移未完成"的结论。
  · IPC$ 连不上（错误 67 / 64）不再刷屏：明确"IPC$ 只是管理共享，连不上不影响数据共享直连，
    只影响凭据用在哪个资源上"，同一主机同一错误码只完整提示一次，之后只记"已出现 N 次"
    （第 2/10/100/1000 次）。连接策略本身没有改动。
  · 如实说明（未改动、也不是本版卖点）：断点续传只到"对象级"——已完成的对象不会重传，
    但被中断的那个大文件是从头重传的（robocopy /Z 会把目标文件预分配到全尺寸，无法判断已写到哪；

    最终 SHA-256 全部一致，数据不会错，只是省不了那一个文件的时间。

■ v0.2.12 修复（重要：迁移完"找不到目标文件夹，但空间确实被占用"）
  · 现象：整盘迁移完成后，在资源管理器里看不到目标文件夹，磁盘空间却实实在在少了。
  · 根因：robocopy 会把"源根目录"的目录属性写到"目标根目录"上，/DCOPY:T 也拦不住。
    整盘迁移的源根就是盘根，而 Windows 盘根天然带 Hidden+System 属性
    （本机实测 C: D: E: 全部是 Hidden, System），于是目标根也被标成隐藏。
    （真机日志里那行「正在复制目标目录属性 D:新建文件夹」就是它干的。）
  · 对策：PCMig 在传输开始、RootFiles 通道结束、任务收尾三处自动清除目标根的
    Hidden/System，并在日志留痕。GUI 新增「📂 目标文件夹」按钮：一键在资源管理器里
    打开目标（打开前也会自动解除隐藏）。
  · 已受影响的历史目标（D:新建文件夹、E:测试）已手工解除隐藏，数据完好。
■ v0.2.11 新增（测试抓出的两个数据准确性问题）

    同时补全了错误码表（32 占用 / 5 权限 / 67 找不到网络名 / 112 空间不足…），
    解析不出错误码时也会原样带出报错原文，绝不吞成"复制失败"。
  · 恢复时"共享不见了"的报错不再指错方向：过去会报 IPC$ 的"找不到网络名"，
    其实真正连不上的是数据共享；现在直接点名该共享（如 \\192.0.2.23\D$），
    并提示到旧电脑运行 net share 确认共享是否还在/改名。

■ 这是什么
  在【新电脑】上运行本工具，输入【旧电脑】的 IP 或电脑名，
  把旧电脑共享出来的磁盘数据完整拉取到新电脑。
  支持：暂停 / 继续、断网断电后断点续传、迁移后数据校验、HTML 报告。

■ v0.2.9 新增（公司真实环境全量测试后加固）
  · 空计划防线：选定的路径全部不存在/不可访问时，明确报 ✘ 失败并说明，
    绝不再显示"✔ 迁移完成 0B"的绿勾错觉（实测踩中：路径少打一个反斜杠）。
  · 恢复更稳：暂停/停止后立刻点恢复，不再偶发"任务被另一个进程持有"——
    程序会自动等对方收尾（最多 30 秒）再接管。
  · 状态文件损坏时 status 会明确提示"损坏"，不再静默显示成新任务。
  另附本次全量测试结论（详见 测试报告-公司环境.md）：
    基线/暂停续传/立即停止续传/杀进程续传/断网自愈 全部通过，
    数据经 PCMig 抽样哈希 + 独立全量 SHA256 双向比对，0 字节差异。

■ 使用前准备（旧电脑侧）
  1. 旧电脑开机并接入内网。
  2. 开启磁盘共享（或确认管理共享 D$ / C$ 可用）。
  3. 准备一个旧电脑上的管理员账号（域管理员可直接用）。
     注意：Win7 目标若使用本地管理员账号，需用内置 Administrator
     （其他本地管理员会被 UAC 远程令牌过滤拦截）。
  4. 防火墙放行“文件和打印机共享 (SMB-In)”。

■ 图形界面用法（PCMig.exe）
  ① 输入旧电脑 IP/电脑名 + 管理员凭据 → 点【连接并列出共享】
     · 主机框支持直接粘贴 \\IP\共享名（如 \\192.0.2.50\D$），连接后自动定位该共享
     · 用户名/密码可留空：此时用当前 Windows 身份直连（同资源管理器）；
       若对方拒绝，会明确提示需要输入凭据
     · 若该电脑有未完成的迁移任务，会自动弹窗询问"是否从中断处继续"
  ② 选择要迁移的内容：
     · 目录树（默认）：共享=根节点。勾共享=整盘；点 ▶ 就地展开，
       目录和文件都可勾选。勾父级=子项全带；取消某子项→父级变半勾 ■，
       其余保持勾选。半勾父级再点=恢复全勾。
     · 超大数据模式（勾选右上角开关）：上亿文件/几十 TB 的服务器级
       迁移专用。目录树替换为「共享勾选 + 排除规则输入框」，规则每行
       一条：/XD 目录名或路径、/XF 文件名或通配符（裸词按目录处理，
       # 开头为注释）。规则与扫描、传输、验证同口径，并存入任务档案。
  ③ 选择目标路径（新电脑接收数据的位置）与线程数：
     · 线程数即 robocopy /MT（8/16/32/64/128，默认 16）：
       海量小文件或大文件多时调高（64/128）更快；机械硬盘或网络
       较差建议 8/16。线程数随任务存档，续传沿用。
  ④ 点【预检并生成计划】→ 确认对象清单与总量
  ⑤ 点【开始迁移】
     - 【暂停】：传完当前对象后停止（协作式）
     - 【立即停止】：立刻终止当前传输，已传部分保留，可续传
     - 【恢复任务】：从中断处继续（已完成的对象不会重传）
  ⑥ 完成后点【验证】核对数据一致性，【打开报告】查看 HTML 报告

■ 断点续传提醒（断电/断网/误关窗口后）
  · 重新打开工具、连接同一台旧电脑时，如发现上次任务未完成，
    会自动弹窗询问"是否继续"；选【是】即从中断处续传，已完成的
    部分不会重传（以每个对象的完成凭证为准）。
  · 生成新计划时若检测到同主机+同目标有未完成任务，同样会提醒。
  · 命令行下：直接运行 pcmig-cli resume（不带参数）会自动选择
    最近的未完成任务继续；quick/new 加 --yes 时检测到未完成任务
    会自动续传而不是新建。

■ 命令行用法（pcmig-cli.exe，以下 pcmig 均指 pcmig-cli.exe）
  预检:   pcmig-cli preflight --host 192.0.2.50 --user OLD-PC\Administrator
  一条龙: pcmig-cli quick --host 192.0.2.50 --target D:\ --user OLD-PC\Administrator
  指定源: pcmig-cli new --host H --source \\H\D$ --target D:\ --yes
  精细选择: pcmig-cli new --host H --source \\H\D$ --target D:\ --yes
            --paths "\\H\D$\图纸;\\H\D$\报表\总结.xlsx"   （分号分隔，可混目录与文件；quick 同支持）
  线程数:  加 --threads 64   （8/16/32/64/128，默认 16，随任务存档）
  排除规则: --xd "node_modules;临时目录" --xf "*.tmp;*.iso"   （分号分隔多项）
  传输:   pcmig-cli run --job <JOB-ID>
  暂停:   pcmig-cli pause --job <JOB-ID>      （协作式）
  急停:   pcmig-cli stop --job <JOB-ID>       （立即）
  恢复:   pcmig-cli resume --job <JOB-ID>
  状态:   pcmig-cli status --job <JOB-ID> [--watch]
  验证:   pcmig-cli verify --job <JOB-ID> [--level 2]   （level 2 含哈希抽样）
  报告:   pcmig-cli report --job <JOB-ID> [--open]
  列表:   pcmig-cli list

■ 不会迁移的内容（安全边界）
  × 浏览器密码 / 网站登录状态（DPAPI 绑定源机，搬过去也解不开）
  × Windows 凭据、证书
  × 驱动程序、安全软件（GlobalProtect/DLP/EDR 由 IT 统一装）
  × 回收站、休眠文件、pagefile 等系统垃圾（见 matrix 策略）
  → 新机首次使用：浏览器和邮箱需要重新登录，属正常现象。

■ 日志位置（排障必备）
  应用日志: <本机程序数据目录>\Logs\app-*.log / *.jsonl
  任务日志: <本机程序数据目录>\Jobs\<JOB-ID>\logs\
            ├─ job-*.log        任务级日志（文本）
            ├─ job-*.jsonl      结构化日志（可程序分析）
            └─ robocopy\*.log   每个对象的 robocopy 原始日志
  任务状态: <本机程序数据目录>\Jobs\<JOB-ID>\
            ├─ job.json / plan.json / job-state.json
            └─ receipts\        每个对象的完成凭证（断点恢复依据）

■ 常见问题
  Q: 提示无法连接 \\IP\IPC$？
     A: 按顺序检查：目标开机 → IP 正确 → 防火墙 SMB-In → 账号密码 →
        Win7 用内置 Administrator。
  Q: 中途断电/断网了怎么办？
     A: 什么都不用做。重新打开工具，选择该任务点【恢复任务】即可。
  Q: 传输速度异常慢？
     A: 检查网线是否千兆、源机是否机械硬盘、是否有安全软件扫描。
  Q: 报告里“完成(有错误)”？
     A: 打开 HTML 报告看对象明细的错误列，通常是源端文件被锁定
        （让用户退出对应软件后，对该任务重新恢复运行一次即可）。

■ 技术要点（给 IT）
  - 传输引擎: Robocopy 双通道（/MT 多线程批量 + /Z 大文件可续传）
  - 断点机制: 对象级 Receipt 凭证 + robocopy 增量语义，重复执行安全
  - 验证: L1 文件数/字节对账，L2 抽样 SHA-256
  - 策略: matrix\migration-matrix.yaml（排除名单/大文件阈值/凭据边界）
  - 超大规模设计（面向服务器级数据量）:
    · 全程流式枚举，计数用 64 位整型，理论上限 800 万 TB / 92 亿亿个文件
    · 传输进度直接解析 robocopy 输出累计，不反复枚举目标目录
    · 验证器文件清单超 200 万条自动切流式核对（内存有界，结果同样精确）
    · 目录树单目录文件显示上限 5000（勾选目录即含全部，仅影响显示）
    · 目录遍历为迭代式（无递归栈深度限制）；已开启长路径（>260 字符）支持
    · 目标盘空间守护：计划总量超过可用空间时明确阻断/确认
