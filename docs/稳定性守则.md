# PCMig 稳定性守则（自 v0.2.28 起生效）

> 项目已进入**功能冻结**阶段：不再加功能，只做修复与加固。这份文件是之后每一次改动的准绳。

## 一、什么能改，什么不能改

**可以改（必须是为了稳定）**
1. 崩溃、卡死、无响应、界面"点了没反应"类问题。
2. 数据正确性：丢文件、传错、断点续传不完整、校验漏报。
3. 可恢复性：失败后能重来、能续传、不破坏已传数据。
4. 可诊断性：日志、错误提示、崩溃记录是否足以定位问题。
5. 性能与资源：内存/句柄不增长、超大数据盘不卡死界面。
6. 文字、提示、文档的纠错。

**不可以改（除非明确要求）**
1. 新增功能、新增界面元素、新增命令。
2. 改既有交互流程与按钮语义。
3. 改 Job 存档格式、plan.json / state.json 的字段含义——一旦改了，用户手上未完成的任务可能无法续传。
4. 改排除规则的默认值——会让同一份数据两次迁移结果不同。

## 二、每次改动都必须带"证据"

改完至少要有两类独立证据，并写进 `docs/测试报告-公司环境.md`：

1. **复现证据**：改之前能稳定复现（脚本、UIA 读数、日志行、哈希值其一）。
2. **修好证据**：改之后同一条路走通，并用**另一种方法**再确认一遍（不能只看自己那一个读数）。
3. 涉及数据正确性的，必须跑 `tools/stability-test.ps1`（逐文件 SHA256 三方核对）。

## 三、发布纪律

1. **先写日志，再打包**：`docs/更新日志.md`、版本对照表、`docs/使用说明.txt` 三处都写好本版内容，
   才允许跑 `tools/release.ps1`（脚本有 5 道闸门，缺一处直接中止）。
2. 一次只发一个版本号；跳号要写清原因。
3. 交付四件套：安装包 + `Portable` + `更新日志.txt`（记事本可直接打开）+ 工作副本，
   脚本逐个哈希比对，全部 MATCH 才算交付成功。
4. 发布后三项验证：应用内更新日志、记事本打开 `更新日志.txt`、`pcmig changelog`。

## 四、功能冻结后的常规体检

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools/stability-test.ps1 -Rounds 2
```

覆盖：边界命名（中文/空格/#%/括号/超长路径/深层目录/空文件/隐藏文件/同名不同目录/200KB 中等文件/300MB 大文件）、
完整迁移三重核对（自写逐文件 SHA256 + 应用自带 verify + robocopy 清单复核）、
中途杀进程→断点续传、目标文件被篡改→重跑修复。全绿才算这一轮通过。

## 五、已知的稳定性债务（不影响正常使用，但要盯着）

| 项 | 现象 | 触发条件 | 现状 |
| --- | --- | --- | --- |
| 进度轮询 | 每 2 秒统计已传字节，超大目录会占 CPU | 目标目录几十万文件量级 | 已用 Job 存档 + 增量估算缓解，继续观察 |
| 校验器内存 | 文件数达数千万时内存偏高 | 单盘 5000 万文件以上 | 未复现（公司环境没有这种量级），暂不动 |
| 暂停后恢复 | 极少数情况下已传字节需重算一次 | 暂停且跨进程重启 | 功能正确，只是慢，可接受 |
| `resume` 不带 --job | 会自动挑"最近的未完成任务"，可能不是你想续的那个 | 机器上存在多个未完成任务 | CLI 语义如此；GUI 里请用任务列表点选，别用裸 resume |

## 六、出了问题怎么查（给自己和用户的操作顺序）

1. 先看**是不是有对话框在等你**：未指定归属窗口的对话框曾禁用整个界面，让按钮"点不动"（v0.2.27 已修）。
2. 看左栏「提示」面板与状态栏文字（都带时间戳，能看出是否真的又跑了一次）。
3. 看日志：应用日志 `%ProgramData%\PCMig\Logs\app-*.log`；崩溃另有 `crash-*.log`；
   任务日志在 `%ProgramData%\PCMig\Jobs\<JOB-ID>\logs\job-*.log`。
4. 复现不了就先跑 `tools/stability-test.ps1`，先排除环境因素。
