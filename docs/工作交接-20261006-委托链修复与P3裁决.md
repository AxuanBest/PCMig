## 2. 本会话做了什么（按主题，含每一处代码坐标）

### A. 场景 H 根因定位（**结论已定论**）

**现象**（2026-10-05 真机）：42 GiB 的 `big` 共享迁往只剩 1.6 GB 的目标盘，**一字节未落盘**，界面却报 **99.9% / 41.95 GB**，而对象完成数 **0/41**；`job-state.json` 记 `completedBytes=45097156608`（= 42×1024³，精确 GiB 整数倍）、`percent=99.9`、`phase=running`、`bytesPerSecond≈10.8 GB/s`（物理不可能）。**污染状态比夹具强制拆卷早 68 秒冻结**，故「拆卷致错乱」不成立。

**★ 根因（四环链，已实测证实）★**：

1. `src\PCMig.Core\Transfer\TransferOrchestrator.cs` 把「转发给 UI」的 `OutputLine` 订阅器注册在 **`OnRunnerErrorLine` 之前**（旧序 `:412` 转发 UI、`:413 OnRunnerErrorLine`）；
2. robocopy 每一行先送达 UI 转发器，转发器在**引擎线程**上直接调 `MigrationSessionViewModel.AddFail`（`MigrationSessionViewModel.cs:3616 if (isError) AddFail("引擎输出", line);` —— **全类唯一一处引擎线程直调**），其 `FailItems.Add` 写 `ObservableCollection` 抛异常；
3. `src\PCMig.Core\Transfer\RobocopyRunner.cs:631` 的空 catch 吞掉异常，**但多播委托中途抛出会终止后续订阅器调用** ⇒ 排在后面的 `OnRunnerErrorLine` **永不执行**；
4. `OnRunnerErrorLine` 是**唯一**填充 `_failedCreditPaths` 与 `_spaceCode` 的地方 ⇒ **回冲与 T07 熔断双双失效**，`/MT` 通道按「新文件 8.0 g」行全额入账，6 个大文件共 42 GiB 永久留在分子上，被 `ProgressTruthSnapshot.RunningPercentCeiling = 99.9` 夹成 99.9%。

**定位过程中的两个教训（勿重复踩）**：

- 我最初把根因误判为「正则硬要求『正在复制文件』⇒ 盘满错误行解析失败」，并据此写了一份报告。**该结论被实测推翻并已重写**（详见 `SCENARIO-H-ROOT-CAUSE-20261006-REV2.md`）。真实错误行形态为
  `2026/10/05 21:44:00 错误 112 (0x00000070) 正在复制文件 \\localhost\PCMIG-DS2\big\big-extra-1.bin`，
  **确实含「正在复制文件」+完整 UNC 路径**，`RobocopyRunner.s_fileErrorRx` 逐字 MATCH=True、`code=112`、path 正确 ⇒ **排除「编码不匹配」与「正则过窄」两类假设**。
- 场景 H 的第二趟（`Pass=Large`）命令行实为 `/MIN:536870912 /MT:16`（**无 `/Z`、无 `/J`**）⇒ 走的是 `_bulkCopiedBytes` + `_pendingCredit` 通道，**不是** `/Z` 通道的 `_largeCompletedBytes`。

## 6. 环境踩坑（**先读这节能省几个小时**）

### 6.2 PowerShell 编码与语言陷阱

1. ★PS 5.1 把没有 BOM 的 `.ps1` 按 **GBK** 解码★：中文（尤其全角括号）会吞掉闭合引号并报 `Missing ')' in method call`；中文路径被毁（`docs\更新日志.md` → `docs\鏇存柊鏃ュ織.md`）。**规则：`.ps1` 必须前三字节 `EF BB BF`**；`write` 工具产出**无 BOM**（改完必须复查前三字节），或把「旧串→新串」写成 UTF-8 payload + 纯 ASCII applier。
2. **`$args` / `$Pid` / `$host` / `$HOME` 是只读自动变量** ⇒ 参数名或变量名一律改用 `$cliArgs` / `ProcessId` 等（本轮 D7 夹具就因 `$args` 报错过）。
3. `[IO.File]::ReadAllText('相对路径')` 按进程 CWD 解析 ⇒ **一律绝对路径**。
4. 单命中 `(…).Count` 返回 `$null` ⇒ 用 `@(…).Count`。
5. 断言不许命中自己的注释。

1. **WinUI 树/列表是虚拟化的** ⇒ 每次操作前**重新抓取** UIA 节点，不要复用上一帧的 `BoundingRectangle`（虚拟化后坐标会过时，鼠标点击会选中错误的行）。
